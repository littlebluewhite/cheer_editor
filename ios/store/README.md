# 上架用的草稿（#399）

App Store Connect 要填的字、截圖、審查帳號那支流程。**全部是草稿，網站主人看過才貼。** repo 是公開的：帳號、密碼、email、裝置的識別資料不放這裡（`src/lib/app-store.test.ts` 檢查 email 和 UUID 的樣子）。

| 檔 | 是什麼 |
|---|---|
| `description.md` | 商店頁：名稱、副標題、推廣文字、描述、關鍵字、網址，每句話的根據 |
| `review-notes.md` | 給審查的人的備註（英文要貼的、繁中對照） |
| `privacy-labels.md` | App 隱私權（隱私標示）怎麼勾，勾和不勾的都列 |
| `questionnaires.md` | 年齡分級、加密、法國、數位商品和服務、其他 App 資訊 |
| `screenshots/` | 模擬器拍的截圖（下面「截圖」） |
| `review-sample.cheer` | 範例流程檔：12 個假名隊員、一段合成的節拍聲（8 個八拍，144 BPM）、一段 30 秒口號、4 張站位、5 個動作 |

## 範例流程檔

- 由 `src/lib/store-sample.ts` 產生，音樂是程式合成的「咚、嗒」節拍聲，沒有別人的歌。改了那支，跑 `STORE_SAMPLE_WRITE=1 npx vitest run src/lib/app-store.test.ts` 重寫檔；`npm test` 會比對檔和程式一不一樣、打不打得開、有沒有音樂、名字是不是假的。
- 打得開：App 裡在 iOS 27.2 模擬器上 `xcrun simctl openurl` 打開過（截圖 `screenshots/iphone-6.3/01-view-flow.png` 就是它）；網頁版用的是同一個 `readFlowFile`（測試）。網頁版在瀏覽器裡用手開，沒試。
- **網站主人要做**：用審查帳號登入網頁，在首頁「開啟流程檔」打開它，按「☁ 傳上雲端」。審查期間伺服器要開著（#302）。

## 截圖

尺寸照 #362 留言（App Store Connect 版本 1.0 頁面上寫的）；拍的時候狀態列固定 9:41、電池滿格，語言繁中。

| 資料夾 | 裝置 | 尺寸 | 有的 |
|---|---|---|---|
| `screenshots/iphone-6.3/` | iPhone 18 Pro 模擬器（iOS 27.2） | 1206 × 2622 | `01-view-flow.png`（範例流程的檢視畫面）、`02-home.png`（首頁） |
| `screenshots/ipad-13/` | iPad Pro 13 吋（M5）模擬器（iOS 27.2） | 2064 × 2752 | `01-home.png`（首頁，直拿） |

模擬器是沒有視窗的，指令點不了畫面、轉不了方向，所以只拍到「打開 App」「打開流程檔」到得了的畫面。**網站主人要補拍的**（Xcode 的模擬器，開 `review-sample.cheer`；也可以用 ⌘S 存模擬器的截圖）：

1. **iPad 橫拿的編輯畫面**（最重要：iPad 只有橫拿能編；直拿的打開流程只有「請把 iPad 轉成橫的」）。尺寸 2752 × 2064。最好停在「三組技巧」那張站位、看得到時間軸。
2. iPad 橫拿的八拍表（上方列「八拍表」）。
3. iPhone 的八拍表（「選單」→「八拍表」，選一個隊員）。
4. iPhone 的練習畫面（「練習」）記成功率。
5. （可以不拍）iPad 的列印畫面。
6. 換掉 `ipad-13/01-home.png`：右下角有一條模擬器留下的彎線（不是 App 的畫面）。

上傳第一個建置以後，再看 App Store Connect 哪幾種尺寸是必填（#362）；要 6.9 吋或別的尺寸就再拍。

## 網站主人要在 App Store Connect 填的（repo 裡不放）

- App 審查資訊：審查帳號的 email、密碼（登入資訊欄）；要不要第二個審查帳號（刪除帳號那顆鈕會真的停用，#325）；聯絡人姓名、電話、email。
- 審查備註裡的空位：`<雲端流程的名字>`、第二個帳號、範例檔的網址（不給就刪那段）。
- 版權欄的法定姓名；主要類別、次要類別；內容版權那題（`questionnaires.md`）。
- 年齡分級「使用者產生的內容」那題要不要答「有」（`questionnaires.md` 的「要注意」）。
- 副標題、推廣文字、關鍵字只是建議，可以改。
- 截圖：上面要補拍的，和上傳建置後才知道的必填尺寸。
