# 雲端流程的一步：伺服器比對前後找出改到的東西，復原送舊的樣子再整份檢查，id 改成亂數

雲端流程的一步送三樣東西：步驟 id（亂數）、「我上次看到第幾步」、一串指令（名字＋參數，教練按的確定、保留／清掉也在參數裡）。伺服器在現在的樣子上照順序跑那串指令，再比一比跑之前和跑之後，哪些東西變了（新增、改、刪都算），那就是這一步改到的東西。伺服器記下每一步：第幾步、哪個分頁送的、改到哪些東西，留 30 天。你上次看到之後，有別的分頁改過同一個東西，或指令被擋、要問，這一步就退回（ADR 0010）。別的分頁收到的是改好之後的那些東西，不是指令；送的分頁收到的「收了」也帶同一份。

本機流程的復原是整份換回舊的流程。雲端不能這樣做，會蓋掉別人的改動。所以雲端的復原、重做也是一步：送那一步改到的東西改之前（重做是改之後）的樣子。伺服器先看那些東西後來有沒有被別的分頁改過，再用新寫的「整份流程檢查」檢查放回去的結果。因為東西沒被碰過，放回去也可能違反規則：你刪了 5 個隊員（剩 35），別人加了 5 個（40），你復原就變 45 人。

流程裡新東西的 id 改成種類字母加 12 個字的亂數（小寫字母、數字），例：`x7k2m9qa4b1z`。這些 id 由步驟 id 算出來，伺服器跑同一步時算出一樣的 id。本機流程也一起換。

## Considered Options

- **比對前後（選這個）**：53 個指令不用改。
- **每個指令自己說改到什麼**：要改 53 個指令，漏寫一個就漏擋。
- **伺服器記每一步（選這個）**：復原、斷線重連都用得到。
- **每個東西只記最後被第幾步改**：比較省。可是你改 x1、別人改 x1、你又改 x1，你連按兩次復原時，看起來 x1 最後是你改的，就會蓋掉別人的改動。
- **復原送舊的樣子，再整份檢查（選這個）**：兩個人一起改時還能復原自己的步。
- **你那一步之後，別人改過任何東西就不能復原**：不用新寫檢查，但兩個人一起改時幾乎都不能復原。
- **把改好的東西送給別人（選這個）**：大家看到的一定跟伺服器一樣。
- **轉送指令，每台自己跑**：訊息比較小。可是各家瀏覽器切字的版本不同（ADR 0013），極少數情況會跑出不一樣的結果，沒人發現。
- **id 用亂數（選這個）**：前端自己發，斷網的手機也能發。
- **每個分頁、手機先跟伺服器拿代號，再自己編號**（例：`x.k7.3`）：id 比較短，但多一個發代號的流程要顧。
- **亂數 8 個字**：比較短。可是一支流程一年幾萬筆紀錄，每年約千分之一的機會撞到；撞到時手機送上來的紀錄會被當成重送的，悄悄不見。

決定的細節在 #193。

## Consequences

- 「同一個東西」：ADR 0010 列的動作（裡面的環節、組、拍點都算在動作裡）、站位裡的一個人（位置＋走法）、段、隊員；另外流程名字、場地、時間規則、標記用號碼還是開頭字各算一個；一張站位的時間（在哪段、第幾拍）、每個任務角色、每個音樂檔各算一個；段的順序、名單的順序各算一個，只有調順序才算改到，加、刪不算。例：改場地會動到每張站位的每個人，跟任何人拖人都會撞。
- 同一個人的兩個分頁也算別人，會互相退回。
- 一步可以帶好幾個指令（例：放音樂＋段長對齊音樂），照順序跑，整串全算或全不算，復原時算一步。方向鍵連按每按一下送一步，復原時照現在合成一步。
- 要確認、要選的指令不送清單：多刪到別人剛加的東西，就是改到別人改過的，退回；你那邊不用問、伺服器那邊要問，也退回。紀錄不算東西，剛記的幾筆會一起清掉。
- 伺服器跑指令時把紀錄放回流程（紀錄分開存，ADR 0011），跑完照結果清掉該清的紀錄。
- 復原照 ADR 0007：伺服器記下每一步清掉、改掉了哪些紀錄（遷移 0017），復原時這一步清掉、到現在還清掉著的加回來，改掉、之後沒再動過的換回改之前的樣子；之後才改過、刪掉的照現在的。重做照結果再清一次。送的分頁也收到跟著改的紀錄（一般的步也是：進房間拿到的紀錄可能還沒算到還沒收的步，連回來時那一步可能早就收了）；自己改了、還在等回答的那幾次先不換（那份比自己的改動舊）。
- 一步被退回時，同一個分頁後面送出的步也一起退回。退回的訊息寫最後改到那個東西的人；被規則擋下就加上指令的原因。
- 伺服器跑出來的可能跟送的人自己畫面上的不一樣：兩個人從同一份各加一個隊員，兩步都收，可是後到的人被伺服器放在別的位置、排在後面，他自己畫面上兩個人疊在一起。所以「收了」帶伺服器做出來的改動（後來加的欄位，部署前開著的分頁不看它）。前端記著伺服器的樣子（自己收了的、別人的改動照第幾步接上；房間不一定照順序說，接不上的先留著），收了之後畫面換成伺服器的樣子，再跑一次還沒收的步；跑不過就先不換，等伺服器退回。復原紀錄裡那一步的重做也換成伺服器做出來的改動（不然復原再重做又疊在一起），順序：這一步加回來的放在復原前畫面上它前一個的後面，其他照現在畫面上的（伺服器的順序裡有別人加的，整份照它重做會把別人後來調的順序調回去）；調順序的那一步照復原前畫面上的順序。「上次看到第幾步」照接上的算：自己的第 2 步收了、別人的第 1 步還沒到，就還是第 0 步，斷線重連才會補上第 1 步。
- 步驟 id 讓斷線重送不會套兩次，重送的「收了」也帶那一步的改動。上次看到的那一步超過 30 天、已經沒留了，這個分頁就換成伺服器的樣子；超過 30 天的步不能復原。
- 要新寫「整份流程檢查」：人數上限、同一個人兩個動作撞在一起、名字長度等，現在都散在各指令裡（`isFlow` 只檢查型別和參照）。只在復原、重做、把 zip 傳上雲端時跑。一般的一步不跑：伺服器自己跑指令，結果本來就合規則，而且檢查要是寫得比指令嚴，一般的步會莫名被退回。
- 前端現在送的是包好的函式；要改成用名字找得到的指令，新東西的 id 改從參數來（ADR 0013）。
- 流程檔升到第 15 版：新的 id 是亂數，不再寫 `lastIds`；舊檔的 `x1` 不用改。舊的編輯器打不開第 15 版，照現在的規則提示更新編輯器。
