# 組用固定 id；紀錄留在流程裡，復原時照組 id 帶紀錄、不問

動作裡的人的組，存的是組 id（`g1`、`g2`…），不是「第幾組」。組 id 用流程的 id 發號，跟環節 `p`、一次 `t`、全上 `r` 一樣，刪了不重用；只在自己的動作裡有意義，從別的動作複製人時照組號對，兩個動作不會共用同一組。組號（第 n 組）不存：動作裡現在有人的組照 id 發出的先後排，第一個是第 1 組。一組空掉，後面的組號自然往前補；紀錄指到組 id，不用跟著換號。教練看到的組名、分組浮動列的號碼、數字鍵、總表都用算出來的組號，跟以前一樣。

紀錄（一次一次的記號）還是存在動作裡，也就是在會復原的流程裡。紀錄不算復原的一步，所以復原、重做換上舊的流程時，要把現在的紀錄帶過去：每個動作用現在的紀錄，指到不在的動作、環節、組 id、隊員的拿掉。帶的時候照組 id 帶，不問教練、不換組：組裡的人變了，紀錄還是留在那個組 id 上。（ADR 0007 推翻了「清掉的紀錄復原也救不回來」：那一步自己清掉的紀錄，復原時加回來、重做再清一次。）

這修正了 ADR 0003 原本那句「流程核心的指令都回傳新的流程，存一串舊流程就好」：紀錄在流程裡，所以復原不只是換回舊的流程，還要帶紀錄。

以前組存的是號碼，組空掉要補號，紀錄跟著換號；復原時同一組在兩份流程裡號碼可能不一樣，只好比對「是不是同一群人」來找它（#59 的 review 一連改了 8 次，最後一次就是復原時紀錄跑到補過號的別組）。改成固定 id 後，核心的「帶紀錄」不再需要對組號。流程檔因此升到第 8 版（`docs/flow-file-format.md`）：開第 7 版的檔時，每個動作的組照號碼順序發組 id，紀錄的「誰」換成那一組的 id。

## Considered Options

- **組用固定 id，紀錄留在流程裡（選這個）**：改的地方集中在組和紀錄的核心、流程檔多一步升級；畫面只換成用算出來的組號。
- **紀錄搬出流程**（放到不會復原的另一份）：復原就真的只是換回舊的流程。但要改所有讀紀錄的地方和流程檔格式，收穫跟固定 id 差不多。
- **復原時問教練**（組換了人，紀錄要留還是清）：教練按復原就是要馬上回去，跳出問題反而打斷；而且留在原來那一組就是對的。
- **照舊存號碼**：每改一條組或紀錄的規則都要記得補號、跟著換號、復原時對人，漏一處就是 bug。

## Consequences

- 一次的「誰」一律是字串：分組的動作是組 id，騰翻、跳躍是隊員 id。
- 組號只能從動作算（`squadsOf`、`squadNumber`），不能從組 id 看出來；畫面要顯示第幾組都要經過核心算。
- 復原後某一組的人跟記的時候不一樣（例：第 2 組加了一個人、記一次、復原），紀錄還是算在那一組上，不問。組 id 不在了，紀錄才拿掉，重做也救不回。
- 舊的編輯器打不開第 8 版的檔，照現在的規則提示重新整理、更新編輯器。
