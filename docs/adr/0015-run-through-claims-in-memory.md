# 一起記全上：誰拿著哪幾組只放伺服器記憶體，同一組同一次只收先存的

好幾個人可以一起記同一次全上，一組在一次全上只由一個人記（ADR 0011、#186）。記的時候，伺服器要知道誰在那張全上表裡、誰拿著哪幾組、那一組點過記號沒，才能讓大家看到誰在記、讓別人接手。這些只放伺服器的記憶體，不存資料庫：手機每次連上伺服器（斷線回來、伺服器重開後都是），自己再報一次「我在哪次全上、拿著哪幾組、點過哪幾組」。真正擋住「一組記兩次」的是存下來的紀錄：一次全上的一組（騰翻、跳躍是一個人）只收一筆，先存的那筆算，後到的不收。

為什麼可以只放記憶體：拿著哪幾組只是讓站在一起的人協調，丟掉幾秒沒關係；每次推 `main` 部署伺服器都會換一台（#194），手機幾秒內就連回來重報。為什麼還要擋存下來的紀錄：伺服器分不出斷線和關掉網頁，斷線的人照樣在記、晚一點才傳上來；別人接手了同一組，兩筆都會送到。只靠記憶體裡的「誰拿著」擋不住，記憶體也可能剛清空。

## Considered Options

- **只放記憶體，手機重報（選這個）**：不用多一張表，也不用清掉沒人關的表。伺服器重開時，表裡的狀態靠手機補回來。
- **存進資料庫**：伺服器重開不會丟。可是要多一張表、要清掉沒人關的表；「誰連著」本來就只能放記憶體，還是要跟手機對。
- **同一組同一次只收先存的（選這個）**：守住名詞表的「一組在一次全上只由一個人記」，成功率不會算兩次。
- **兩筆都收，像分段練**：紀錄永遠不會被擋。可是重複的要人自己找出來刪，沒刪的話那組那次全上算兩次。

決定的細節在 #195。

## Consequences

- 紀錄第一次會因為「別人已經記了」不收。ADR 0011 說紀錄不像流程的一步會被退回，指的是兩個人改同一筆；這裡是多出來的新一筆。後到的那筆進手機上「沒存進去」的清單，寫「王教練已經記了這次全上的第 2 組」。表還開著時，那一欄馬上變灰。
- 一欄第一次點記號時送一次給伺服器，不是每點一格都送。搶同一組、或剛點下去時別人同時接手，照伺服器收到的先後，後到的退回並提示。
- 斷線超過 1 分鐘，就當那個人離開那張表：他拿著的組（點過的也算）別人都能接手。表裡的人都離開了，就不能再加入。他連回來，表還在手機上就回到表裡，沒被接手的組還是他的。斷網時開的表，連上後也一樣能讓別人加入。
- 一次全上要記開的時間（手機的時間），一天裡的全上照開的時間排第幾次；全上的 id 是亂數（ADR 0014），不能再用號碼排。流程檔第 15 版多這一欄；舊檔沒有開的時間，照舊的號碼排，排在有時間的前面。
