# 房間規則先不搬進伺服器：QuickJS 一步超過 50 毫秒，改用共用的情境檔對齊

「這一步收不收」（收過的步驟 id、權限、前一步被退回、太久、復原的 30 天、改到同一個東西、被規則擋下、紀錄跟著清掉或加回來）現在寫在流程核心的 `takeStep`（`src/lib/core/room-step.ts`，#315），假伺服器叫它。#308 階段 6 說：先在伺服器的 QuickJS 裡量，1 MB 的流程一步在 50 毫秒以內（ADR 0013 量到的範圍）才讓 Rust 改叫它，超過就不搬，改做共用的情境檔。

量到的：插入一個八拍一步約 90–98 毫秒，復原一步約 150–164 毫秒，都超過 50 毫秒。

**決定：#323 做共用的情境檔，Rust 伺服器不改叫 `takeStep`，房間規則照舊留在 Rust（`server/src/flow_room.rs`、`server/src/records.rs`）。** 同一份情境（JSON）在 Vitest 跑假伺服器（流程核心的 `takeStep`），在 cargo test 跑真的伺服器，兩邊結果不一樣就失敗。

## 量的方法

- 測試：`server/src/flow_core.rs` 的 `room_step_timing`（平常不跑）。`cd server && cargo test --release --lib -- --ignored --nocapture room_step_timing`。
- 流程：`server/tests/fixtures/big-flow.js` 用流程核心的指令做：36 人、80 個動作（每個 3 個環節、兩組）、80 張站位、5,500 次紀錄。不帶紀錄的編排 139,760 bytes，紀錄 1,155,001 bytes，整支含紀錄 1,045,430 bytes（約 1 MB）。
- 三種步：改流程名字（幾乎只有 JSON 進出）、在最前面插入一個八拍（後面 80 個動作、80 張站位全部往後挪）、復原改名字。
- 步驟紀錄：0、100、1,000、5,000 筆（`takeStep` 要的是上次看到之後、和要復原的那一步之後的每一步，不先挑分頁、改到的東西）。每筆是別的分頁改了一個隊員，沒有清掉的紀錄。
- 從 Rust 傳 JSON 字串進 QuickJS、拿 JSON 字串回來，包含在時間裡。每種先跑 3 次暖身，再跑 25 次，記最快和中位數。每次都檢查結果是「收了」，不是早早退回。
- 機器：Apple M3 Max（16 核）、macOS，`--release`（rquickjs 0.14、rustc 1.98.1），2026-11-21。跑的時候這台機器同時在跑別的工作（load average 約 18–30），所以同一個量尺也跑一次比對（下表第一段）。數字只能看量級，不等於 Fly.io 機器上的數字。

## 另外量到的：現在的伺服器也超過 50 毫秒

現在的伺服器每一步叫兩次流程核心（跑指令、再比對前後），插入一個八拍約 101 毫秒、復原約 173 毫秒，已經超過 ADR 0013 寫的「25–50 毫秒」。`takeStep` 一次做完，量到的不比現在慢（改名字約 45 對 56、插入一個八拍約 90–98 對 101、復原約 154–164 對 173）。ADR 0013 的數字是整支含紀錄跑一個指令，沒有算到紀錄分開存（ADR 0011）之後的放回、拿出和比對前後。

這張照 #308 定的門檻（一步 50 毫秒以內）決定。如果之後要改用「不比現在慢」當門檻，要重新開這個決定；上面的數字可以直接用。

## Considered Options

- **Rust 改叫 `takeStep`，規則只有一份 TypeScript**：門檻沒過（插入一個八拍約 90 毫秒、復原約 155 毫秒）。
- **共用的情境檔（選這個）**：Rust 的規則和速度都不動；兩份規則靠同一份情境對齊，不一樣就失敗。
- **維持現狀（假伺服器手抄、沒有情境檔）**：已經對不上過好幾次（e3ef238 修過一次重做；30 天前的步不能復原假伺服器沒抄）。不要。

## Consequences

- ADR 0013「規則只有一份 TypeScript」在房間規則這裡不成立：房間規則有兩份，Rust 伺服器一份、流程核心的 `takeStep` 一份（假伺服器用），靠情境檔對齊。指令本身（`runCommands`、`runUndo`、整份流程檢查）照舊只有一份 TypeScript，伺服器用 QuickJS 跑。
- `takeStep` 留在流程核心（假伺服器用它）；`bundle-entry.ts` 的 `takeStepJson` 先留著，給以後再量用。
- 改房間規則（`flow_room.rs` 的 `take_step`、`records.rs` 的 `brought_back`、`after_step`）時，同一個 commit 改 `takeStep`，加一份情境。
- #323 先放的情境：假伺服器以前跟 Rust 不一樣、`takeStep` 照 Rust 改過的地方：
  - 收過的步驟 id 先於權限檢查（檢視者重送收過的步，回原本的結果）。
  - 檢視者、記錄者送步被退回之後，接著送的、上次看到還在之前的也退回（被退回的那一步記下第幾步）。
  - 上次看到的下一步已經沒留：退回「太久」。
  - 要復原的那一步超過 30 天：退回「太久以前的，不能復原」。
  - 改了的紀錄（例：復原換回原來的組）跟同一次全上別人存的那一筆撞在一起：只算先存的，這一筆清掉。
- 以後流程核心變快（或伺服器換更快的 JS 引擎），用同一個測試再量；過了門檻再考慮讓 Rust 叫 `takeStep`，到時候要傳進去的：現在的編排和第幾步、這支流程的紀錄（連清掉的、`amended_step`）、上次看到和要復原那一步之後的步驟紀錄（每筆的分頁、名字、時間、改到的東西、清掉的紀錄）、收過的步驟 id 那一步的結果、權限、這個連線被退回時第幾步、現在的時間。存、鎖、流程被刪了、權限被收回、退回的中文句子、音樂哪天不用了，留在 Rust。
