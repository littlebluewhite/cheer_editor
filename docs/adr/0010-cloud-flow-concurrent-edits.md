# 雲端流程大家同時改，改到同一個東西時後到的退回

> 編號：雲端這邊的 ADR 原本是 0007–0012，跟 main 合併時改成 0010–0015（舊 0007 → 0010、0008 → 0011、0009 → 0012、0010 → 0013、0011 → 0014、0012 → 0015）。已經跑過的遷移（`server/migrations/` 的 0001–0016）註解裡寫的是舊編號，不改（sqlx 會比對 checksum）。

可以編輯的人可以同時打開、同時改同一支雲端流程，不上鎖。每一步做完就送到伺服器，伺服器照收到的先後一步一步套上去。一步要嘛整步算，要嘛整步不算。某一步改到的東西，在這個人上次看到之後已經被別人改過，這一步就退回；跟別人的改動合起來會違反流程的規則，也一樣退回。退回時告訴那個人，例：「王教練剛改了同一個地方，你的『拖動作』沒改成」。他的畫面換成伺服器上的樣子，再做一次就好。「同一個東西」指的是同一個動作、同一張站位裡的同一個人、同一個段、同一個隊員。

開圖時我們猜，通常一次只有一個教練在改，所以上鎖就夠用。但網站主人選了大家同時改：兩個人可以分頭改不同的地方，不用互相等。我們很多步會一次改很多東西：插入八拍會把後面的動作都往後挪，刪掉一個段會連帶刪掉動作和站位。如果後到的直接贏，會悄悄變成奇怪的位置，而且沒人發現；退回再做一次比較好懂。

## Considered Options

- **後到的退回，告訴他（選這個）**：兩人改不同的東西不會互相擋。改到同一個東西很少發生，退回一次還能接受。
- **上鎖，一次一個人改**：最省工，現在整份存、整份復原都能照用。但另一個教練只能等，不能分頭改。
- **後到的贏，不說（Figma、Linear 的做法）**：不會退回。但一步改很多東西時會悄悄混在一起；合起來違反規則的，要伺服器自己猜怎麼修。
- **CRDT（Yjs、Automerge、Loro）**：能離線改、自動合併。可是我們沒有長文字要一起打；CRDT 不管流程的規則和權限，合完還是要檢查；前端也要多一個套件。

研究筆記：`research/concurrent-editing` 分支的 `docs/research/concurrent-editing.md`（#179）。決定的細節在 #185。

## Consequences

- 復原只復原自己的步。你的那一步改到的東西後來被別人改過，這一步就不能復原：提示之後跳過，再按一次就試前一步。重做也用同一條規則。
- 先改自己的畫面，不等伺服器。一步被退回時，這一步和後面還沒送到的步一起退回。
- 伺服器要知道流程的規則（現在寫在 TypeScript 的流程核心），每一步套上去之後都要再檢查一次。
- 流程裡新發的 id 不能再從流程依序發號（`x1`、`g1`…），因為兩個人同時加東西會撞號。這改了 ADR 0006 裡「組 id 用流程的 id 發號」的那部分，流程檔的格式也要跟著改。
- 要一條一直連著的線（WebSocket）：送改動、收別人的改動、列出現在誰開著這支流程。
- 沒有存檔鍵，也沒有以前的版本可以退回（第一版不做）。
- 改雲端流程一定要有網路：一斷線就不能改，連上後再送還沒送到的步。
