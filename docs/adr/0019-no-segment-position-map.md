# 改段的指令不改成產生位置對照表：試做兩個指令，流程核心多了 24 行

#308 階段 7（#324）說：先在插入八拍、刪段兩個指令試，讓指令產生一張「舊位置 → 新位置或拿掉」的表，書籤、動作和站位的位置照表搬；流程核心（不算測試）少掉的行數比加的多、全部測試綠，才把段縮短、切段也做完，不划算就停下，寫這份 ADR。

量到的：**加了 32 行、少了 8 行（多 24 行）**，測試全綠，但沒有划算。

**決定：不做位置對照表。四個改段的指令（插入八拍、刪段、段縮短、切段）照舊各自搬自己的東西，每個指令後面那次「掃一遍」書籤（`commands.ts` 的 `run()` 叫 `sweepBookmarks`）照舊。之後的架構檢查不用再提這件事，除非下面「什麼時候重開」的情況出現。**

## 試做的樣子

- 一個新的流程核心 module（`segment-map.ts`，19 行，含開頭說它管什麼、不管什麼的註解）：`SegmentMap = (p: TimePosition) => TimePosition | null`，`insertMap(at, length)`、`deleteMap(segmentId)`，加上從 `index.ts` 匯出（1 行）。
- 插入八拍（`insert-beats.ts`，+8 −6）：原本的 `moves`／`later` 兩行換成照表算；站位、動作的新時間從表讀。
- 刪段（`segment-order.ts`，+4 −2）：要刪的動作照表挑。
- 量法：`git diff --numstat refactor/308-architecture -- src/lib/core ':(exclude)src/lib/core/*.test.ts'`，新 module 整個算進去，旁邊的程式沒有為了數字改短。核心的 `insert-beats`、`segment-order`、`bookmarks`、`anchored-range`、`commands` 測試不用改就全過（236 個）。
- 試做的程式沒有合進去（2026-11-21）。

## 為什麼少不了

表能取代的只有每個指令裡本來就一兩行的「這個時間點搬到哪」：插入八拍的 `moves`／`later`、刪段的 `a.segmentId === segmentId`、切段的 `moved`。改段的指令大部分的行數是後果，表管不到：

- **書籤**：已經在錨在段上的範圍 module（`anchored-range.ts`，#312）。插入八拍時 B 剛好在插入點不動、B 在段尾留在段尾（`afterInsert`），切段時 B 剛好在切點留在前一段段尾（`afterSplit`），刪段拿掉 A 或 B 在那段的（`touches`）、段縮短拿掉跨出新段尾的（`pastEnd`），只看那一段；段換順序拿不拿掉才是「換好段之後放不放得下」（`bookmarkSeconds`）。B 是結尾、不是一個時間點，單純的「時間點 → 時間點」表會搬錯，要另外寫結尾的規則，等於再抄一份 `afterInsert`。
- **插入八拍擋不擋**：超過段尾時要說卡最緊的是哪個、最多插多少，站位、出發和到達要在段裡（`end - 1 - at`），動作的結尾可以剛好是段尾（`end - start - length`），書籤兩頭又不一樣。每一種東西的「還能晚幾格」不同，留在指令裡。
- **開頭那張站位**：插入八拍不動它；刪段時「跟著新的第一段」（`reorder`：新的第一段開頭本來有站位就接手，沒有就把那一刻大家所在的地方記下來）。這不是位置的搬法。
- **走位**：照預設走、在插入點以前出發的人，把出發記成自己設的（不然插入點以前站的地方會變）。
- **要問的清單**：刪段、段縮短要先列出會刪掉、裁短的東西（還要算紀錄幾次），流程還沒改之前就要知道。
- **段縮短**：跨出段尾的動作是裁短（拍點、環節、紀錄照動作變短的規則），不是搬也不是拿掉，表上寫不出來。

動作和站位的時間點寫法也不一樣（動作是 `segmentId`＋`start`，站位是 `segmentId`＋`at`，開頭那張的 `segmentId` 可以是 null），照表搬每個地方都要先包成 `TimePosition` 再拆回來，所以換掉的兩行變成更多行。

## Considered Options

- **四個指令都產生對照表**：試了兩個就多 24 行；段縮短的裁短、切段的 B 規則都要表以外的程式，做完只會更多。不要。
- **只有插入八拍、刪段用表**：兩種寫法並存，比現在難讀，又沒有少行。不要。
- **照舊（選這個）**：每個指令自己搬，書籤經過 `anchored-range.ts`，每個指令後面掃一遍書籤當保險。

## Consequences

- 改段的指令沒有共用的「位置對照」；新增一個改段的指令時，書籤用 `anchored-range.ts` 的函式搬，動作、站位、走位在指令裡自己搬，`run()` 後面的 `sweepBookmarks` 會拿掉放不下的。
- 什麼時候重開：多了一種要跟著段搬、而且搬法就是單純時間點的東西（例如新的標記），四個指令都要各寫一次時；或改段的指令變成要在伺服器上合併別人的改動（要把一個人的改段套到別人的位置上），需要一張可以傳的表時。
