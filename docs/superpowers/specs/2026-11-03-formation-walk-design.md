# 站位好排：人不亂跑、誰什麼時候走、看得到路線、能復原

設計文件，2026-11-03。名詞照 `GLOSSARY.md`（走位、出發、到達、站位）。決策紀錄見 `docs/adr/0004-walk-depart-arrive.md`。

## 為什麼要做

教練每張站位都要拖人，很累。原因是兩張站位之間，每個人用整段時間慢慢直線走（`positionsAt`）。在中間任何一拍拖人，自動插出來的站位裡大家都「走到一半」。想讓人站著不動，就得每一張都拖回去。

真實的流程是：大部分時間站著做動作，某一個八拍才移動；而且有人先走、有人後走（例如跑翻：10 號、9 號、8 號一個接一個）。

**示範（丟棄用的原型）**：分支 `worktree-prototype-formation-hold` 的 `prototypes/formation-hold.html`（commit `c3b2ded`），有 7 個示範頁。它只是參考；跟這份文件不一樣的地方，以這份文件為準。

## 要做的（一次全部做）

1. **① 跟上一張一樣**：選人，按一下，他們回到上一張站位的位置。
2. **② 往後帶**：改了一個人的位置，後面還站在舊位置的站位會自動跟著改。
3. **③ 出發和到達**：每個人可以設自己什麼時候出發、什麼時候到達。沒設的人最後一個八拍才走。
4. **④ 復原和重做**：所有改流程的操作都能復原。
5. **⑤ 影子、走位線、走太快標紅**。
6. **⑥ 拖人之前就知道會改哪一張站位**。
7. **⑦ 個人八拍表寫走位**。

## 不做的

- 站位在時間上移動（照 ADR 0003）。
- 彎的走位路線。要繞路，就在中間多插一張站位。
- 改「預設最後一個八拍」的長度（沒有全流程的設定）。要別的長度，就全隊選起來再設。
- 「跟下一張一樣」。
- 走位時間自動對齊騰翻動作的時間。
- 復原紀錄在重新整理之後還在。
- 在場地上拖走位時間（只在表單和泳道上改）。

## 做了也算失敗的

- 舊檔打開後，任何一張站位裡的位置變了。
- 拖人（包括自動插站位）讓**沒被拖的人**的走法變了。
- 復原之後，選到的人、選到的站位或動作指到不存在的東西。
- 全隊 40 人都畫線時，場地被線蓋住、看不清楚。

## 規則

### 走位的時間

兩張相鄰的站位叫 A（前）和 B（後）。

- 一個人在 A、B 的位置不一樣，就走位一次。位置一樣，就整段站著。
- 出發之前站在 A 的位置。出發到到達之間直線等速。到達之後站在 B 的位置等。
- **沒設的人（預設）**：
  - 到達 = B 的時間。
  - 出發 = B 往前一個八拍（8 拍，用 B 所在音樂段的 BPM 換成秒數），但不早於 A。
  - B 在口號段：出發 = A，也就是整段走。
  - A、B 之間不到一個八拍：整段走。
- **自己設的**：存在 B 上，每人一組出發和到達。
  - 時間跟站位一樣，記「哪個段 ＋ 段內時間」（音樂段第幾個半拍，口號段第幾個 0.1 秒），所以改 BPM 時還是同一拍。
  - 到達可以早於 B（早到的人站著等），出發可以晚於 A。
  - 計算時夾在 A、B 之間。夾完如果出發不早於到達（例如後來改了段長），就當作沒設，用預設。
- 開頭那張前面沒有站位，所以不會有出發和到達。

### 插站位（拖人自動插，或按 ① 時插）

**不能變的規則**：插之前和插之後，每個人每一刻的位置都一模一樣。

插在時間 t。看每個人原本 A→B 的走位（出發 s，到達 e）：

- t ≤ s：新站位裡他在 A 的位置（還沒走）。B 上維持原本的 s、e。
- s < t < e：新站位裡他在半路。新站位記 [s, t]，B 記 [t, e]。
- t ≥ e：新站位裡他已經在 B 的位置。新站位記 [s, e]，B 那段他不動。

只有「不寫，預設就會算出不一樣的結果」時才需要寫進去。寫多寫少由 builder 決定，用上面那條規則測。

### 刪站位

刪掉 B（開頭那張不能刪）：B 上的出發和到達設定一起刪掉。B 後面那張的設定留著，計算時夾在新的間隔裡。走法會變，這本來就是刪站位會發生的事。

### 刪隊員

各張站位裡這個人的出發和到達設定一起刪掉。

### ① 跟上一張一樣

- 要先選人。沒選人時按鈕不能按，旁邊寫「先選人」。
- 播放頭在站位 B 上（B 不是開頭那張）：選到的人在 B 的位置，改成上一張 A 的位置。
- 播放頭不在站位上：跟拖人一樣，先插一張，再改成上一張的位置。效果就是「他們到這一拍都還站著」。
- 播放頭在開頭那張：按鈕不能按，寫「開頭那張前面沒有站位」。
- 改完照 ② 往後帶。整個操作算復原的一步。

### ② 往後帶

- 任何改位置的操作（拖人、①）都會往後帶。
- 對每個被改的人：記下他在這張站位的舊位置 p。往後一張一張看，他在那張也在 p（同一點，容許 1e-9 誤差），就一起改成新位置。遇到第一張他不在 p 的，就停下來，後面都不動。
- 有往後帶到時，提示「後面 N 張站位也跟著改了」（N = 被改到的站位張數）。如果同時也插了站位，兩句話合成一則提示。
- 整個操作（包括插站位、往後帶）算復原的一步。

### ③ 設出發和到達

有兩個地方可以設：

**1. 表單**
- 播放頭在站位 B 上，而且 B 不是開頭那張時，才會出現。
- 有兩個欄位：出發、到達。寫法用八拍寫法（例如 `2-5`），跟動作表單的寫法和解析一樣。
- 有選人：只改選到的人。沒選人：改全隊（不管有沒有走位都寫）。
- 按「套用」才改。旁邊有「用預設」，按了會清掉選到的人（沒選人就是全隊）的設定。
- 擋下來的情況：出發不早於到達、時間不在 A 和 B 之間。擋下來時用提示說原因，不改流程。

**2. 泳道**
- 每個人自己的泳道裡，每一次走位畫一條「走位條」，從出發畫到到達。走位條要跟動作色條分得開，例如畫成細條、貼在泳道下緣。
- 拖左端改出發，拖右端改到達，拖中間兩端一起挪。
- 吸附跟動作色條一樣：音樂段半拍，口號段 0.1 秒。
- 不能拖出 A、B 之間，出發要早於到達。
- 有選人，而且被拖的人也在選取裡：選到的人只要在同一個間隔裡有走位，就一起挪一樣多拍。碰到邊界時，照場地上整組拖人的做法處理。
- 放開才改流程。被擋就還原，跟動作色條一樣。

### ④ 復原和重做

- **範圍**：所有改流程的操作都算，包括站位、動作、段、隊員、設定、名稱。播放頭、選取、放大縮小、捲動不算。
- **一步是什麼**：流程換成新的一次就是一步。例如拖人放開、按 ①、套用走位、拖走位條放開、存一個動作表單、改段設定。
- 最多記 100 步。開檔、新建、還原草稿時清空。不存進草稿，也不存進檔案。
- **按鍵**：⌘/Ctrl+Z 復原；⌘/Ctrl+Shift+Z 和 Ctrl+Y 重做。游標在文字框或下拉選單裡時不攔，讓瀏覽器自己復原打的字。
- **按鈕**：上方列加「復原」「重做」兩個按鈕，沒東西可以復原或重做時不能按。
- 復原之後，選到的人、站位、動作如果已經不存在，就清掉（`+page.svelte` 現在已經有這段，照用）。
- 已經解碼的音樂不能因為復原而丟掉，復原再重做之後還要能播。
- 復原之後，草稿照常自動存，存的是復原後的流程。

### ⑤ 影子、走位線、走太快

- **播放頭在站位 B 上**（B 不是開頭那張）：上一張 A 的位置畫成淡淡的影子點；位置有變的人，從影子畫一條線到他現在的點。
- **播放頭在兩張站位中間**：畫這段 A→B 的走位線（從 A 的位置到 B 的位置），點本來就會沿著線動。
- 有選人時只畫選到的人；沒選人時畫全隊。
- 線要淡，不能擋住點。線不吃滑鼠，點人、拖人、框選都跟以前一樣。
- **走太快**：距離 ÷（到達 − 出發的秒數）> 每秒 4 公尺，就把線標紅，泳道上那條走位條也標紅。
  - 如果這個人在走位期間，跟他自己參加的騰翻動作時間重疊，就不標紅。
  - 4 m/s 寫成一個常數，之後好改。這個數字是猜的，還沒跟教練確認過。
- 八拍表上的小站位圖不畫影子和線。

### ⑥ 拖人之前就知道會改哪一張

場地旁邊放一行小字，跟著播放頭變：

- 在站位上：「拖人會改：站位 3（2-1）」
- 不在站位上：「拖人會在 2-3 插一張新站位」
- 在開頭那張：「拖人會改：站位 1（開頭）」

站位編號是照時間排的第幾張，跟站位縮圖列上的號碼一樣。拍子寫法用 `src/lib/core/time.ts` 現有的那一套（音樂段 `3-5&`，口號段秒數）。

### ⑦ 個人八拍表寫走位

- 只印一個隊員時：他每走位一次，就在「出發那一拍所在的那一列」加一行：「2-5 出發 → 站位 3（3-1 到）」。
- 不寫「走」這個字，因為他可能是用跑的，也可能是在騰翻。
- 同一列也有他的騰翻動作時，兩行都寫：動作那行說做什麼，走位那行說到哪裡。
- 全隊的八拍表不變。
- 口號段的時間，照口號段原本的寫法（秒數）。

### 檔案格式（第 2 版）

- 站位多一個可有可無的欄位 `walks`，只有自己設過的人才有：

  ```json
  { "id": "f3", "segmentId": "s1", "at": 64, "pos": { … },
    "walks": { "m6": { "depart": { "segmentId": "s1", "at": 48 }, "arrive": { "segmentId": "s1", "at": 64 } } } }
  ```

- 開頭那張不會有 `walks`。
- 檢查：隊員 id 要存在、段 id 要存在、`at` 是 ≥ 0 的整數。不對就照現有規則提示「這不是流程檔」。
- `FORMAT_VERSION` 改成 2。第 1 版升第 2 版時資料不用動，沒有 `walks` 就是全部用預設。但舊檔的走法會照新的預設變（教練已經同意）。
- 更新 `docs/flow-file-format.md`：「站位」那節的走位規則、「插站位」那句，再加上 `walks` 的說明。

## 怎樣算做完

- **核心單元測試（Vitest）**，至少要測：
  - 預設走法：音樂段、口號段、不到一個八拍、跨段。
  - 自己設的走法，以及時間超出間隔時夾回去。
  - 插站位：插之前和插之後，抽很多個時間點比對每個人的位置，要一模一樣。
  - 刪站位、刪隊員。
  - ①（包括擋下來的情況）。
  - ② 遇到第一張不一樣的就停。
  - 第 1 版檔案升級、`walks` 的檔案檢查。
- **元件測試（jsdom）**，至少要測：
  - 泳道拖走位條：一個人、整組。
  - 場地的影子和線：有選人時只畫選到的。
  - ⑥ 那一行字。
  - 復原和重做的按鈕與快捷鍵，包括在文字框裡時不攔。
  - 個人八拍表的走位那一行。
- 舊的測試裡，跟「整段慢慢走」綁在一起的，要照新預設改，並把改了哪些列出來。
- 使用說明頁（`/guide`）的文字要補上新功能。截圖要不要重拍，由 builder 決定。
- 在真的瀏覽器裡用滑鼠試一次：拖人、拖走位條、復原。

## 留給 builder 決定的

- 畫面版面、顏色、按鈕放哪裡。上面有寫出來的字要照寫。
- 函式名稱，以及復原紀錄怎麼存。
- 插站位時哪些人要寫進 `walks`：寫最少或全寫都可以，用「不能變的規則」來測。
- 表單裡，選到的人設定不一樣時要顯示什麼。
- 整組拖走位條碰到邊界時怎麼處理（照場地上整組拖人的做法）。

## 這些是我（Claude）替教練決定的，請教練看過

- 拖人時自動插站位要留著，另外加上 ⑥ 的提示。
- 播放頭不在站位上時按 ①：先插一張站位，再對齊上一張。
- 口號段沒有拍子，所以整段走。
- 「一個八拍」用 B 所在音樂段的 BPM 換成秒數。
- 刪站位時，後面那張的設定留著。
- 表單裡沒選人時，全隊都寫入設定。
- 復原最多記 100 步；開檔、新建、還原草稿時清空；重新整理之後不留。
- 走太快的標準是每秒 4 公尺；在騰翻動作裡的人不標紅；泳道上的走位條也一起標紅。
- 個人八拍表寫「出發 → 站位 N（幾拍到）」，不寫「走」字。這是回答教練問的「跑翻寫走位會不會錯」。
