# 流程影片：把整支流程做成一支手機看的 MP4

設計文件，2026-11-18 定稿；**2026-11-19 做完（#270，子票 #271–#276），這份照做出來的樣子改過一次**。之後行為有出入時以程式碼為準：`src/lib/core/video-frame.ts`、`src/lib/video/`、`src/lib/components/VideoExport.svelte`。給使用者看的說法在使用說明 4.9 的「輸出影片」。
名詞照 `GLOSSARY.md`（流程影片、流程、段、音樂段、口號段、八拍、八拍表、站位、走位、動作、任務角色、拍點、拍子、步驟、手位、環節、標記、中層、上層）。
研究和實測：`docs/research/video-export.md`。試驗頁 `prototypes/video-export-spike/index.html` 用完已經刪了，要看在 commit 036ff8e。

## 為什麼要做

隊員拿到流程檔，要打開編輯器才看得到流程。教練要一支影片，隊員在手機上點開就能看：大家站哪、怎麼走，每個動作每一拍做什麼。資訊要完整，停在哪一格都看得懂。

issue #12 原本寫「匯出影片不做」（太花工）。這份文件改掉那個決定。

## 要做的

1. 編輯器多一個按鈕「輸出影片」，按了做出一支流程影片（MP4），存成 `流程名.mp4`。
2. 影片是直的，1080×1920，每秒 30 格，給手機看。
3. 整支流程從頭到尾、正常速度、有音樂、沒有節拍器聲。
4. 上面是場地，下面是全隊八拍表現在這一列，加一排 1–8，現在這拍亮起來。

## 不做的

- 個人版（只看我）。只做全隊。
- 只輸出一段、慢速、加節拍器聲。
- 橫的影片。
- iPad、手機上輸出（按鈕不出現），所以也沒有「分享」，只有存檔。
- Mac 的 Safari 上輸出（Safari 26 以上說做得出來，但編碼器有已知 bug，沒測過）。
- Firefox、舊 Safari、Linux 的 Chrome 上輸出（瀏覽器做不出 AAC 聲音）。要用另外帶的聲音編碼器（`@mediabunny/aac-encoder`）才做得到，它是 LGPL，不帶。
- 改流程檔格式。流程影片不進流程檔，`FORMAT_VERSION` 不動。
- 傳到 LINE 等通訊軟體、上傳到雲端。只存檔。

## 做了也算失敗的

- 影片裡的位置、拍點跟編輯器播放時對不上（差一格畫面以上）。
- 聲音跟畫面對不上，或某一段的音樂接錯位置。
- 資訊被悄悄切掉：放不下的東西沒提示就不見。
- 手機上字小到看不清楚。
- 做到一半當掉、卡住，或取消不了。
- 輸出時教練還能改流程，改的東西一半進影片一半沒進。
- 編輯器打開變慢（沒輸出也載入了影片套件）。
- 不能離線用的時候，連編輯器也壞掉。

## 規則

### 時間

- 開頭先停 2 秒：寫流程名和「開場站位」，沒有 1–8 那一排，場地是流程開頭的站位，沒有聲音。
- 接著從流程第 0 秒播到結尾，跟編輯器按播放一樣。
- 結尾停 1 秒，畫面停在最後一格。
- 影片第 t 秒的畫面 = 流程第 t − 2 秒（夾在 0 到結尾之間）。

### 每一格畫什麼

全部問流程核心，跟編輯器播放時用的同一套：

- 位置：`positionsAt(flow, sec)`；疊起來的人：`layersAt`（每個人在第幾層）；標記：`memberMarkers`。
- 場地的幾何：`fieldGeometry`；條號、格號、「正面／裁判」的位置也在 `src/lib/core/field.ts`，`Field.svelte` 和影片共用。
- 疊起來的人（跟編輯器的場地一樣）：第 2 層（中層、上層、支撐）黃框，第 3 層（三層）橘框。跟下面一層的人站在同一點的圓點往右上錯開、縮小（每高一層 ×0.85），被別層站在同一點的人蓋住的人畫虛線圈；只是站在隔壁（圓點碰到邊）的照原樣畫。同一層的人照名單順序畫（隊員 id 是數字也一樣）。算法在 `src/lib/core/layer-stagger.ts`。
- 下面那一列：全隊八拍表現在這一列（`eightCountRows(flow, null)` 裡 `startSec ≤ sec` 的最後一列）。整支影片只算一次八拍表（`videoFrames`），不是每一格重算。
- 跟八拍表不一樣的兩點：
  1. 還在做的動作，每一列都寫全誰和任務角色，不只寫「↳ 名字 繼續」。影片隨時會被暫停，停在哪都要看得懂。
  2. 八拍表把連著沒事的八拍合成一列；影片的上方照樣寫現在第幾個八拍，不寫「5–8」。
- 場地上的字要在手機上看得清楚：整個場地照原本的比例塞進 1080 寬，圓點上的標記只有約 5 pt，太小。所以跟手機檢視畫面一樣把圓點放大：圓點至少 64 px（手機檢視的 22 px ÷ 0.36），標記 32 px；錯開縮小的圓點，標記也不小於 28 px。條號、格號、「正面／裁判」不小於 28 px。站得很近（約 1 公尺）的人，圓點會疊到，可以接受。整個場地都畫，不裁切。
- 標記很長、人又站在場地左右邊上時，標記會超出影片被切到。圓點不移位；輸出前對話框列出這些隊員（每一格都看，照畫的字級量）。
- 走位線、影子、撞位 ✕、組號不畫。它們是給教練編排用的提醒；隊員看影片只要知道站哪、怎麼走。（編輯器裡播放時有些照樣會畫，影片不跟。）

### 口號段

- 沒有聲音（編輯器播放也一樣）。
- 上方寫「口號 1・12.3 秒」（段裡過了幾秒），沒有 1–8 那一排。
- 下面那一列是口號段整段那一列。

### 放不下時

- 流程名一行放不下：字從 56 px 縮到 40 px，還放不下就換兩行，第二行尾巴「⋯」。
- 下面那一列不能捲。放不下時字從 40 px 每次縮 2 px，縮到 28 px 就停。28 px 在手機上（1080 寬縮成約 0.36 倍）約 10 pt，網站主人用手機看過，看得清楚（#275）。
- 縮到 28 px 還放不下，照這個順序拿掉，放得下就停：
  1. 還在做的動作，從寫全誰和任務角色縮成「↳ 名字 繼續」（從最下面那個開始縮）。
  2. 備註。
  3. 整個動作，從最下面拿起，最後一行寫「⋯還有 N 個動作」。至少留一個動作；一個都沒寫出來時，N 是全部的動作。
  4. 還是放不下（例：一個動作的「誰」那一行本身就太長）：在區塊底截掉，尾巴加「⋯」，不蓋到別的字。
- 拍點和環節那 8 格：一格寫不下就把那一格拉高，字照樣寫完。拍點多到那一區放不下時，放不下的那幾行不畫，寫「⋯還有 N 行拍點」；後面放得下的照畫。
- 輸出前先算一遍，有放不下的八拍就在對話框列出來（「這幾個八拍有東西放不下，會縮成一行或拿掉：音樂 1 第 6 個八拍、…」，合起來的列寫「第 6–8 個八拍」），教練可以照樣輸出。

### 聲音

- 照 `playbackPlan(flow, 0)` 的音樂片段，混成一軌，往後挪 2 秒（開頭停的那段）。不放節拍器聲。
- 48 kHz、雙聲道、AAC 128 kbps。
- 找不到音樂、音樂檔壞了、還沒選音樂的段：那段沒聲音，照樣輸出。輸出前對話框寫出是哪幾段和音樂檔名（例：`音樂 1「x.mp3」`、`音樂 2（還沒選音樂）`）。每一段都沒有聲音時，影片沒有聲音軌。

### 檔案

- MP4：H.264 Constrained Baseline（`avc1.424028`，level 4.0）＋ AAC-LC。每 2 秒一個關鍵格。
- moov 放前面（手機邊下載邊播）。
- 檔名：`流程名.mp4`，不能放進檔名的字換成「_」，流程名是空的就叫 `流程.mp4`。存檔另外寫一個 `saveVideo`（`src/lib/file/save.ts`），不用流程檔那一套（那套綁著打開的 `.zip`，會蓋掉流程檔）：Chrome、Edge 每次都跳存檔對話框問存哪裡，不記上次的檔；沒有存檔對話框就下載。存檔失敗寫看得懂的原因。

### 哪裡可以輸出

- 只在電腦的畫面（不是窄螢幕、不是觸控螢幕）出現「輸出影片」，在八拍表按鈕旁邊；練習畫面沒有。檢視模式也可以輸出（不會改到流程，跟八拍表一樣）。窄的時候只留攝影機圖示。
- 只開 Chromium 系的瀏覽器（Chrome、Edge）。
- 打開對話框時當場問瀏覽器做不做得出 `avc1.424028` 1080×1920 30 fps 和 AAC 48 kHz 雙聲道（用跟真的編碼一樣的畫質、bitrate 問）。不是 Chromium 或做不出：對話框寫「這個瀏覽器不能輸出影片，請用電腦的 Chrome 或 Edge」，沒有「開始」。
- 影片工具（`mediabunny`）載不下來（例：離線、service worker 還沒存好）：寫「影片工具載不下來，請連上網路再試一次；還是不行，請重新整理頁面」，有「再試一次」。
- 流程沒有段：按鈕停用，滑鼠移過去寫「先加一段」（跟播放一樣）。

### 輸出時

1. 按「輸出影片」→ 對話框：寫影片多長、放不下的八拍、沒有聲音的段、標記會被切到的隊員，按「開始」。
2. 輸出中：進度條，「做到第 N 格／一共 M 格」，「取消」（Esc、點背景也算取消）。對話框蓋住編輯畫面，不能改流程、不能播放。
3. 做完：寫檔案多大，按「存檔」才存（存檔對話框要使用者剛按過按鈕才叫得出來，做了一分多鐘之後不算）。這時 Esc、點背景不會關掉，免得做好的影片沒存就不見；只有「存檔」「關閉」。
4. 失敗：寫看得懂的原因（三種之一），瀏覽器原本的錯誤訊息用小字寫在下面，可以「再試一次」。
5. 取消或關掉對話框：丟掉做到一半的東西。聲音還在編時取消也馬上停，不包成 MP4。
6. 用的是按「開始」那一刻的流程。

## 做法

| 做法 | 怎麼做 | 好處 | 壞處 |
|---|---|---|---|
| **A. 一格一格畫，再編碼（選這個）** | 照流程秒數一格一格畫在 Canvas 上，聲音用 OfflineAudioContext 混好，用 WebCodecs 編碼，`mediabunny` 包成 MP4 | 不用等即時播放（3 分鐘的流程在 M3 Max 的 Chrome 約 33 秒做完）；分頁切到背景也不會掉格；每一格的時間算得準 | 場地要用 Canvas 再畫一次，跟 `Field.svelte` 的樣子可能慢慢對不上 |
| B. 錄下即時播放 | `canvas.captureStream()` ＋ `MediaRecorder` | 少寫一點 | 3 分鐘的流程要錄 3 分鐘；切到別的分頁會停、掉格；Firefox 做不出 MP4 |
| C. 把場地的 SVG 每一格轉成圖片 | 序列化 `Field.svelte` 的 SVG → 圖片 → 畫到 Canvas | 場地跟編輯器長得一模一樣 | 一格要解一次 SVG，5,000 多格很慢；樣式（CSS 變數、scoped class）要另外塞進去 |

選 A。B 不能保證每一格都在，C 太慢。

A 的壞處（兩邊長得慢慢不一樣）這樣減少：

- 場地算位置的程式（條號、格號、`NUMBER_BAND`、`fullView`、「正面／裁判」）搬進 `src/lib/core/field.ts`，`Field.svelte` 和影片都問它。
- 影片的顏色另外抄一份（`src/lib/video/colors.ts`），`colors.test.ts` 讀 `Field.svelte`、`EightCountCueLine.svelte` 和 `app.css` 的原始碼，比對兩邊的色碼一樣（跟 `source-guards.test.ts` 同一種做法）。

套件：`mediabunny`（MPL-2.0，1.66.0）。原本的 `mp4-muxer` 已經被作者標成不再維護、叫人改用它。它已經繞過 Safari、Firefox 編碼器的幾個已知 bug。照原樣用、不改它的檔案；授權說明在建置時產生的 `third-party-licenses.txt`，使用說明最下面有連結（#276，見 `docs/deploy.md`）。

## 程式怎麼分

- **流程核心（`src/lib/core/video-frame.ts`）**：純函式算「影片第 t 秒這一格要寫什麼」：上方的字、1–8 哪格亮、位置、層、下面那一列（含還在做的動作的人）。不碰 Canvas，用 vitest 測。
- **版面（`src/lib/video/layout.ts`）**：把那一格排進 1080×1920。量字用 Canvas 的 `measureText`，收成一個參數，測試換成假的（跟 `toMeters` 一樣的做法，ADR 0002）。「放不下」的判斷、標記超出影片的判斷都在這裡。
- **畫（`draw.ts`）**：拿排好的版面畫到 Canvas。不測內容，靠實際看。
- **編碼（`encoder.ts`、`fake-encoder.ts`）**：adapter（跟 `src/lib/audio/engine.ts` 和 `fake-engine.ts` 一樣）：真的用 `mediabunny`，測試換成假的。`mediabunny` 用動態 `import()` 載入，編輯器打開時不載（建置後自己一個 chunk，約 235 KiB，會被 service worker 先存起來，見 `docs/deploy.md`）。
- **對話框（`VideoExport.svelte`）**：元件測試用假的編碼器，測開始、進度、取消、失敗、存檔、瀏覽器不支援、工具載不下來。

## 實測（細節見 `docs/research/video-export.md`）

- 速度：3 分鐘的流程（183 秒、5,490 格）在 M3 Max 的 Chrome 約 33 秒做完；動作少的約 13–15 MB，動作多的約 34 MB。
- 手機播放、手機上的字、LINE 傳到手機再打開、輸出中切到別的分頁：網站主人試過，都沒問題（#275）。
- 離線輸出：試過，可以（`docs/deploy.md`）。

## 還沒做的

- **Windows 沒測過**（#275 沒有 Windows 可以試）。一般筆電（Intel／AMD）也沒量過速度。
- 「標記會被切到」的檢查在真的瀏覽器要花多久沒量過（測試環境裡約 85 ms）。
- `videoRow`（`video-frame.ts`）和八拍表各寫了一次「哪些動作還在做」。沒有東西壞掉，先不合：八拍表會丟掉沒有隊員的動作，硬合起來影片可能少畫東西。要合的話，先決定影片要不要也丟掉沒有隊員的動作。
