# 流程影片：把整支流程做成一支手機看的 MP4

設計文件，2026-11-18。名詞照 `GLOSSARY.md`（流程影片、流程、段、音樂段、口號段、八拍、八拍表、站位、走位、動作、任務角色、拍點、拍子、步驟、手位、環節、標記）。
研究：`docs/research/video-export.md`。試驗：`prototypes/video-export-spike/index.html`（用完就丟）。

## 為什麼要做

隊員拿到流程檔，要打開編輯器才看得到流程。教練要一支影片，隊員在手機上點開就能看：大家站哪、怎麼走，每個動作每一拍做什麼。資訊要完整，停在哪一格都看得懂。

issue #12 原本寫「匯出影片不做」（太花工）。這份文件改掉那個決定。

## 要做的

1. 編輯器多一個按鈕「輸出影片」，按了做出一支流程影片（MP4），存成 `流程名.mp4`。
2. 影片是直的，1080×1920，每秒 30 格，給手機看。
3. 整支流程從頭到尾、正常速度、有音樂、沒有節拍器聲。
4. 上面是場地，下面是全隊八拍表現在這一列，加一排 1–8，現在這拍亮起來。

## 不做的

- 個人版（只看我）。只做全隊。
- 只輸出一段、慢速、加節拍器聲。
- 橫的影片。
- iPad、手機上輸出（第一版連按鈕都不出現）。
- Mac 的 Safari 上輸出（Safari 26 以上說做得出來，但編碼器有已知 bug，沒測過）。
- Firefox、舊 Safari、Linux 的 Chrome 上輸出（瀏覽器做不出 AAC 聲音）。要用另外帶的聲音編碼器才做得到，它是 LGPL，先不帶。
- 改流程檔格式。流程影片不進流程檔，`FORMAT_VERSION` 不動。
- 傳到 LINE 等通訊軟體、上傳到雲端。只存檔。

## 做了也算失敗的

- 影片裡的位置、拍點跟編輯器播放時對不上（差一格畫面以上）。
- 聲音跟畫面對不上，或某一段的音樂接錯位置。
- 資訊被悄悄切掉：放不下的東西沒提示就不見。
- 手機上字小到看不清楚。
- 做到一半當掉、卡住，或取消不了。
- 輸出時教練還能改流程，改的東西一半進影片一半沒進。
- 編輯器打開變慢（沒輸出也載入了影片套件）。
- 不能離線用的時候，連編輯器也壞掉。

## 規則

### 時間

- 開頭先停 2 秒：寫流程名和「開場站位」，場地是流程開頭的站位，沒有聲音。
- 接著從流程第 0 秒播到結尾，跟編輯器按播放一樣。
- 結尾停 1 秒，畫面停在最後一格。
- 影片第 t 秒的畫面 = 流程第 t − 2 秒（夾在 0 到結尾之間）。

### 每一格畫什麼

全部問流程核心，跟編輯器播放時用的同一套：

- 位置：`positionsAt(flow, sec)`；上層、中層：`raisedAt`；標記：`memberMarkers`。
- 場地的幾何：`fieldGeometry`。
- 下面那一列：全隊八拍表現在這一列（`eightCountRows(flow, null)` 裡 `startSec ≤ sec` 的最後一列）。
- 跟八拍表不一樣的兩點：
  1. 還在做的動作，每一列都寫全誰和任務角色，不只寫「↳ 名字 繼續」。影片隨時會被暫停，停在哪都要看得懂。
  2. 八拍表把連著沒事的八拍合成一列；影片的上方照樣寫現在第幾個八拍，不寫「5–8」。
- 場地上的字要在手機上看得清楚：整個場地照原本的比例塞進 1080 寬，圓點上的標記只有約 5 pt，太小。所以跟手機檢視畫面一樣把圓點放大（`VIEW_MIN_DOT_PX` 的做法，換算成影片的大小），標記、條號、格號、「正面／裁判」都不小於 28 px。站得很近（約 1 公尺）的人，圓點會疊到，可以接受。整個場地都畫，不裁切。
- 走位線、影子、撞位 ✕、組號不畫。它們是給教練編排用的提醒；隊員看影片只要知道站哪、怎麼走。（編輯器裡播放時有些照樣會畫，影片不跟。）

### 口號段

- 沒有聲音（編輯器播放也一樣）。
- 上方寫「口號 1・12.3 秒」（段裡過了幾秒），沒有 1–8 那一排。
- 下面那一列是口號段整段那一列。

### 放不下時

- 畫面不能捲。下面那一列放不下時，字一級一級縮小，縮到下限就停。
- 下限：手機（寬 390 pt 左右）上看起來約 10 pt。1080 寬的影片在那種手機上縮成約 0.36 倍，所以畫的時候不小於 28 px。這個數字實作時要在真的手機上看一次再定。
- 縮到下限還放不下，照這個順序拿掉，放得下就停：
  1. 還在做的動作，從寫全誰和任務角色縮成「↳ 名字 繼續」（從最下面那個開始縮）。
  2. 備註。
  3. 整個動作，從最下面拿起，最後一行寫「⋯還有 N 個動作」。
- 拍點和環節那 8 格一律留著，不拿掉。
- 輸出前先算一遍，有放不下的八拍就在對話框列出來（「音樂 1 第 6、7 個八拍有東西放不下」），教練可以照樣輸出。

### 聲音

- 照 `playbackPlan(flow, 0)` 的音樂片段，混成一軌，往後挪 2 秒（開頭停的那段）。不放節拍器聲。
- 48 kHz、雙聲道、AAC 128 kbps。
- 找不到音樂、音樂檔壞了的段：那段沒聲音，照樣輸出。輸出前在對話框寫出是哪幾段。

### 檔案

- MP4：H.264 Constrained Baseline（`avc1.424028`，level 4.0）＋ AAC-LC。每 2 秒一個關鍵格。
- moov 放前面（手機邊下載邊播）。
- 檔名：`流程名.mp4`。存檔的做法跟流程檔一樣（Chrome 跳存檔對話框，其他的下載），但要另外寫一個：流程檔的存檔（`src/lib/file/save.ts`）綁著打開的那個 `.zip`，型別也寫死 zip，拿來存影片會蓋掉流程檔。

### 哪裡可以輸出

- 只在電腦的編輯畫面（不是窄螢幕、不是觸控螢幕）出現「輸出影片」。檢視模式也可以輸出（不會改到流程，跟八拍表一樣）。
- 只開 Chromium 系的瀏覽器（Chrome、Edge）。其他瀏覽器按下去直接跳下面那句說明。
- 按下去時當場問瀏覽器做不做得出 `avc1.424028` 1080×1920 30 fps 和 AAC 48 kHz 雙聲道。做不出就跳說明：「這個瀏覽器不能輸出影片，請用電腦的 Chrome 或 Edge」，不開始。
- 流程沒有段：按鈕停用（跟播放一樣）。

### 輸出時

1. 按「輸出影片」→ 對話框：寫影片多長、放不下的八拍、沒有音樂的段，按「開始」。
2. 輸出中：進度條（做到第幾格／一共幾格），「取消」。對話框蓋住編輯畫面，不能改流程、不能播放。
3. 做完：寫檔案多大，按「存檔」才存（存檔對話框要使用者剛按過按鈕才叫得出來，做了一分多鐘之後不算）。
4. 失敗：寫看得懂的原因，可以再試。
5. 取消或關掉對話框：丟掉做到一半的東西。
6. 用的是按「開始」那一刻的流程。

## 做法

| 做法 | 怎麼做 | 好處 | 壞處 |
|---|---|---|---|
| **A. 一格一格畫，再編碼（選這個）** | 照流程秒數一格一格畫在 Canvas 上，聲音用 OfflineAudioContext 混好，用 WebCodecs 編碼，`mediabunny` 包成 MP4 | 不用等即時播放（試驗：10 秒的影片約 5 秒做完）；分頁切到背景也不會掉格；每一格的時間算得準 | 場地要用 Canvas 再畫一次，跟 `Field.svelte` 的樣子可能慢慢對不上 |
| B. 錄下即時播放 | `canvas.captureStream()` ＋ `MediaRecorder` | 少寫一點 | 3 分鐘的流程要錄 3 分鐘；切到別的分頁會停、掉格；Firefox 做不出 MP4 |
| C. 把場地的 SVG 每一格轉成圖片 | 序列化 `Field.svelte` 的 SVG → 圖片 → 畫到 Canvas | 場地跟編輯器長得一模一樣 | 一格要解一次 SVG，5,000 多格很慢；樣式（CSS 變數、scoped class）要另外塞進去 |

選 A。B 不能保證每一格都在，C 太慢。

A 的壞處（兩邊長得慢慢不一樣）這樣減少：

- 現在只有條、墊子、接縫、格線在流程核心（`fieldGeometry`）。條號和格號的位置、`NUMBER_BAND`、`fullView`、中心 X、「正面／裁判」的位置還寫在 `Field.svelte` 裡。把這些搬進 `src/lib/core/field.ts`，`Field.svelte` 和影片都問它。只搬算位置的程式，`Field.svelte` 畫出來要跟原本一模一樣（`npm run check:layout` 和整頁測試都要過；畫面沒變，使用說明不用重拍）。
- 場地的顏色大多寫死在 `Field.svelte` 的 CSS 裡（外圍 `#e4e8ef`、接縫 `#12306a`、上層黃框 `#ffd400`…），只有少數是 `app.css` 的變數。影片另外抄一份顏色常數，加一個測試讀 `Field.svelte` 和 `app.css` 的原始碼，比對兩邊的色碼一樣（跟 `source-guards.test.ts` 同一種做法）。

套件：`mediabunny`（MPL-2.0，1.66.0，2026-11-13 發佈）。原本的 `mp4-muxer` 已經被作者標成不再維護、叫人改用它。它已經繞過 Safari、Firefox 編碼器的幾個已知 bug。照原樣用、不改它的檔案時，我的理解是不用公開我們的程式；這是我的理解，不是法律意見。

## 程式怎麼分

- **流程核心（`src/lib/core/`）**：一個純函式算「影片第 t 秒這一格要寫什麼」：上方的字、1–8 哪格亮、位置、上層、下面那一列（含還在做的動作的人）。不碰 Canvas，用 vitest 測。
- **版面**：把那一格的資料排進 1080×1920。量字寬要用 Canvas 的 `measureText`，所以量字收成一個參數，測試換成假的（跟 `toMeters` 一樣的做法，ADR 0002）。「放不下」的判斷在這裡，也用假的量字測。
- **畫**：拿排好的版面畫到 Canvas。不測內容，靠試驗和實際看。
- **編碼**：收成一個 adapter（跟 `src/lib/audio/engine.ts` 和 `fake-engine.ts` 一樣）：真的用 `mediabunny`，測試換成假的，記下收到幾格、聲音多長。`mediabunny` 用動態 `import()` 載入，編輯器打開時不載。
- **對話框**：元件測試用假的編碼器，測開始、進度、取消、失敗、存檔、瀏覽器不支援。
- **按鈕位置**：上方列在 1024×768 已經很擠，也沒有「⋯」選單（唯一的「⋯」是播放區的延遲校正，不放那裡）。放在八拍表按鈕旁邊，窄的時候跟八拍表一樣只留圖示；`npm run check:layout` 要過。
