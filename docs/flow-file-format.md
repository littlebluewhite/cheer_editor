# 流程檔格式

分層照規格（#15）的「流程檔格式」。讀寫都在流程核心：`writeFlowFile(flow, 音樂位元組)`、`readFlowFile(zip 位元組)`
（`src/lib/core/flow-file.ts`）。範例：`docs/samples/sample-flow.zip`（只用假名）。

## zip 裡有什麼

存成 `流程名.zip`：

```
flow.json        { "formatVersion": 10, "flow": { … } }
audio/a1.mp3     flow.audio 列出的音樂檔，原封不動（zip 裡不再壓縮）
audio/a2.m4a
```

- `flow.json` 只有 `formatVersion` 和 `flow` 兩層。延遲校正之類的本機設定不進檔（延遲校正存在瀏覽器裡，±1000 毫秒，`MAX_LATENCY_MS`；超出就當 0）。
- 開檔時 `flow.json` 不在最上層、而在唯一一層資料夾裡（例：電腦解壓再重新壓縮成 `練習用/flow.json`）也打得開，
  音樂檔照同一個資料夾找（`練習用/audio/a1.mp3`）。Mac 壓縮時多放的 `__MACOSX/` 不算。存檔一律放最上層。
- `flow` 的欄位：`name`、`field`（`strips`、`layout`: `vertical`／`horizontal`）、`timeRules`、`members`、
  `audio`、`segments`、`formations`、`customRoles`、`actions`，可有可無的 `markers`、`lastIds`，下面各節逐一說明。

## 版本（formatVersion）

- 現在是第 10 版。改了 `flow.json` 的格式就把 `FORMAT_VERSION` 加 1，並在 `UPGRADES` 補一步「第 n 版 → 第 n + 1 版」。
- 開舊版檔：一步一步升到現在的版本再打開；存檔一律存現在的版本。
  - 第 1 版 → 第 2 版：站位多了可有可無的 `walks`（見「站位」）。資料不用動，沒有 `walks` 就是全部用預設，
    所以每張站位裡的位置不變；但什麼時候走會照新的預設（先站著，最後一個八拍才走）。
  - 第 2 版 → 第 3 版：動作多了可有可無的 `cues`（見「動作的拍點」）。資料不用動，沒有 `cues` 就是沒有拍點。
  - 第 3 版 → 第 4 版：動作多了可有可無的 `color`（辨識色），站位多了可有可無的 `name`（站位名稱）。
    資料不用動，沒有 `color` 就是用大類的顏色，沒有 `name` 就是只顯示號碼。
  - 第 4 版 → 第 5 版：流程多了可有可無的 `markers`（見「隊員」）。資料不用動，沒有 `markers` 就是用號碼。
  - 第 5 版 → 第 6 版：動作多了可有可無的 `successRate`，動作裡的人多了可有可無的 `squad`，流程多了可有可無的
    `lastIds`（見「動作的成功率設定和組」）。資料不用動，沒有 `successRate` 就是沒打開記成功率，沒有 `squad` 就是沒分組。
  - 第 6 版 → 第 7 版：整理環節和組，讓檔案守第 7 版的規則（見「動作的成功率設定和組」）。
    音樂段的動作裡沒標拍的環節拿掉，連紀錄裡打在它們上面的記號；記號清光的那一次整筆拿掉。
    刪到一個環節都不剩的動作（或本來就沒有環節的）不記成功率：`successRate` 和每個人的 `squad` 都拿掉。
    跳號的組改成 1、2、3（照原來的先後），紀錄的 `who` 跟著改號。口號段的環節不動。
    本來就不守第 6 版規則的檔不整理，照樣是「flow.json 壞掉了」。
  - 第 7 版 → 第 8 版：`squad` 從第幾組（數字）換成組 id（字串，見「動作的成功率設定和組」）。每個動作的組照號碼順序發組 id，
    照動作的順序一直往下發（`g1`、`g2`…）；分組動作的紀錄的 `who` 從號碼換成那一組的 id（騰翻、跳躍的 `who` 是隊員，不動）；
    有發組 id 就在 `lastIds` 記上 `g`。組號不是 1、2、3 連續的檔不換，照樣是「flow.json 壞掉了」。
  - 第 8 版 → 第 9 版：還沒有環節（沒有 `successRate`）的動作也可以有 `squad`（從別的動作複製人帶來的組，加第一個環節時照用）。
    資料不用動；第 8 版以前沒有 `successRate` 的動作有 `squad`，照樣是「flow.json 壞掉了」。
  - 第 9 版 → 第 10 版：紀錄的一次多了可有可無的 `blanks`（見「動作的成功率設定和組」）。資料不用動，
    沒有 `blanks` 就是沒有空著的環節：舊檔裡中途 ✗ 的一次，之後刪掉 ✗ 的環節，後面空著的分不出來，照剩下的記號算。
- 打不開時提示「打不開「檔名」：原因」，原因是下面其中一個：
  - 開比編輯器新的檔：「是新版編輯器存的，請重新整理，更新編輯器」。
  - 不是 zip（zip 壞掉了、拿別的檔來開）：「檔案壞掉了，或不是這個編輯器存的流程檔」；
    檔名是音樂檔（mp3、m4a、wav）時改說「這是音樂檔，不是流程檔」，叫教練去段設定載入。
  - 最上層和唯一一層資料夾裡都沒有 `flow.json`：「zip 裡沒有 flow.json」。
  - JSON 壞掉、沒有 `formatVersion` 或 `flow`、舊版號但沒有升級步驟：「flow.json 壞掉了」。
  - `flow` 裡任何一個欄位的型別不對（例如位置不是 `[x, y]`、分類不在清單裡），或指到不存在的段、音樂檔、隊員：
    也是「flow.json 壞掉了」，不會開到一半壞掉。
- 缺音樂檔照開（見「音樂檔」），提示寫出檔名和缺的音樂檔名。

## 音樂檔

```json
"audio": [{ "id": "a1", "file": "audio/a1.mp3", "name": "第一首.mp3" }]
```

- `file` 是 zip 裡的路徑，`name` 是教練載入時的原始檔名（只給畫面顯示）。
- 只列有段在用的音樂檔；兩個音樂段可以指同一個（變速切段）。
- **缺音樂檔**（`file` 不在 zip 裡）照樣打開：指到它的音樂段標紅「找不到音樂」，點開段設定重新選檔；
  動作和站位都不動。缺的檔下次存檔也不會出現在 zip 裡。

## 段

```json
{ "id": "s1", "kind": "music", "audioId": "a1", "bpm": 150, "firstBeatSec": 0.42, "halfBeats": 192 }
{ "id": "s2", "kind": "chant", "tenths": 300 }
```

- 音樂段：`audioId` 還沒載入音樂時是 `null`；`firstBeatSec` 是第一拍在音樂檔的第幾秒；長度存半拍數。
- 口號段：長度存 0.1 秒數。
- 長度上限（`src/lib/core/segment.ts`）：音樂段最多 `MAX_EIGHTS`（200）個八拍，也就是 `halfBeats` 1 到 3200；
  口號段 0.1 到 `MAX_CHANT_SEC`（300）秒，也就是 `tenths` 1 到 3000。開檔（含救回草稿）時段的長度超出或不是正的就打不開，
  原因寫上限，例：「打不開「檔名」：口號段長度要在 0.1 到 300 秒之間」「…：音樂段要在 1 到 200 個八拍之間」。

## 時間規則、自訂任務角色、動作

```json
"timeRules": { "on": true, "minChantSec": 30, "maxMusicSec": 120, "maxTotalSec": 180 },
"customRoles": [{ "id": "r1", "name": "旗手", "meaning": "拿隊旗跑場的人" }],
"actions": [{ "id": "x1", "segmentId": "s1", "category": "stunt", "name": "Lib", "start": 16, "length": 16,
              "note": "", "members": [{ "memberId": "m1", "role": "上層" }] }]
```

- 固定的 11 個任務角色不存，只存這支流程自己加的。
- 動作的 `category`：`stunt` `pyramid` `toss` `tumbling` `jump` `dance` `other`。
- 動作的 `color`（可有可無）：辨識色，`#rrggbb`。沒有就是用大類的顏色。
- `start`、`length` 是段內整數時間（音樂段半拍、口號段 0.1 秒）；`role` 存角色名稱，沒掛角色是 `null`。

### 動作的拍點（cues）

`cues`（可有可無，沒有就是沒有拍點）：這個動作的拍點。存在動作裡、從動作開始算，所以拖動作、改 BPM 時跟著走，
刪動作時一起刪。

```json
"cues": [{ "kind": "count", "at": 0, "len": 4, "word": "down", "who": null },
         { "kind": "motion", "at": 4, "len": 2, "word": "high V", "who": { "role": "上層" } }]
```

- `kind`：`count`（拍子）、`step`（步驟）、`motion`（手位）。
- `at`：從動作開始算第幾個半拍（0 = 動作開始那一刻）。`len`：幾個半拍長，一拍 = 2。
- `word`：拍子只能是 `down`、`up`；步驟、手位是教練寫的字，去掉頭尾空白後不能是空的。
- `who`：`null` 是動作裡全部的人；`{ "role": "上層" }` 是動作裡這個任務角色的人；`{ "member": "m1" }` 是這個隊員。
- 檢查（不對就是「flow.json 壞掉了」）：
  - `at`、`len` 是整數；`len` 是 2 的倍數、至少 2，手位一定是 2；`0 ≤ at`、`at + len ≤ length`。
  - 只有音樂段的動作可以有拍點。
  - `who` 指到的任務角色要有人在這個動作裡掛著，隊員要在這個動作裡。
  - 不要求在整拍上：在拍點格子上新放的對齊音樂的整拍，動作之後被拖半拍時，拍點跟著落在 &；落在 & 的拍點可以在原位換字。

### 動作的成功率設定和組（successRate、squad）

`successRate`（可有可無，沒有就是不記成功率）：這個動作分成哪幾個環節、記了哪些次。動作有環節才有這個欄位。
動作裡的人可以多一個 `squad`（組 id，可有可無，沒有就是沒分組）：

```json
"members": [{ "memberId": "m1", "role": "上層", "squad": "g1" },
            { "memberId": "m2", "role": "主底", "squad": "g1" },
            { "memberId": "m3", "role": "上層", "squad": "g2" }],
"successRate": {
  "phases": [{ "id": "p1", "kind": "load", "name": "延伸", "beats": { "at": 0, "len": 4 } },
             { "id": "p2", "kind": "hold", "name": "", "beats": { "at": 4, "len": 4 } },
             { "id": "p3", "kind": "dismount", "name": "搖籃", "color": "#c62828", "beats": { "at": 8, "len": 4 } }],
  "records": [{ "id": "t1", "date": "2026-11-04", "who": "g1", "practice": "drill", "whole": true,
                "marks": { "p1": "✓", "p2": "✓", "p3": "△" } },
              { "id": "t2", "date": "2026-11-04", "who": "g2", "practice": "drill", "whole": true,
                "marks": { "p1": "✓", "p2": "✗" }, "blanks": ["p3"] }]
}
```

- `phases`：環節，有順序。
  - `kind`：`load`（上法）、`hold`（中段）、`transition`（轉接）、`dismount`（下法）、`whole`（整體）。
  - `name`：教練取的名字，可以是空字串。
  - `color`（可有可無）：動作辨識色那 9 色或石板灰（`#475569`），`#rrggbb`。沒有就用種類的顏色：上法青、中段石板灰、轉接金、下法紫、整體灰。
  - `beats`：標的拍（音樂段的環節一定有，口號段的環節沒有，口號段不數拍），跟拍點一樣：`at` 從動作開始算第幾個半拍，`len` 幾個半拍長。從音樂的整拍開始（動作開始加 `at` 是雙數），`len` 是雙數、至少 2。
  - `id`：整個流程裡不重複，刪了也不再用（紀錄靠它對回環節）。
- `records`：紀錄，一次一筆，照記的先後排。
  - `id`：整個流程裡不重複，刪了也不再用，例：`t1`。
  - `date`：裝置的當地日期 `YYYY-MM-DD`。
  - `who`：誰，一律是字串。分組的動作是組 id；騰翻、跳躍的動作是隊員 id。
  - `practice`：`drill`（分段練）或 `runThrough`（全上）。全上的多一個 `runThroughId`，同一次全上記的都一樣，例：`r1`（刪了也不再用）。
  - `whole`：`true` 是整個做，`false` 是只練幾個環節。
  - `marks`：每個環節的記號，key 是環節 id，值是 `✓`（成功）、`△`（小失誤）、`✗`（失敗）。空著的環節（✗ 後面沒做到、沒練的）不寫。
  - `blanks`（可有可無，第 10 版起）：整個做、中途 ✗ 的一次，記的時候就有、在 ✗ 後面空著的環節 id。沒有就不寫。
    整次成功率靠它分出「那一次當時就有的環節」：一次算成功要當時就有、現在還在的環節（`marks` 和 `blanks` 裡現在還在的）全是 ✓，
    空著的不算成功；之後才加的環節不在這兩個裡，不看。刪環節時 `marks` 和 `blanks` 裡指到它的一起拿掉；
    `marks` 和 `blanks` 都清光的那一次整筆拿掉（當時就有的環節全被刪光，也就不算進整次成功率）；
    只剩 `blanks` 的那一次留著（`marks` 是空的），照樣算進整次成功率、不算成功。
- `squad`：組 id，`g` 加編號（第 8 版起；第 7 版以前是第幾組的數字）。從流程發號，刪了也不再用；只在自己的動作裡有意義
  （從別的動作複製人時照組號對，兩個動作不會共用同一組）。
  組號（第 n 組）不存：動作裡現在有人的組照組 id 發出的先後（編號由小到大）排，第一個是第 1 組；一組空掉，後面的組號自然往前補，
  紀錄指到組 id，不用改。組的名字是「第 n 組」加上組裡任務角色是上層的人（好幾個就用名單上第一個），也不存。
- 還沒有環節的動作（第 9 版起）：從別的動作複製人時，人身上的組照組號帶過來（發這個動作自己的組 id），畫面上還不顯示組。
- 加第一個環節時有 `successRate`，分組的大類把動作裡全部的人放進新的一組（第 1 組）；已經有人帶著組（上一條）就照那些組，沒帶組的人沒有組。
  最後一個環節刪掉時 `successRate` 和每個人的 `squad` 都拿掉。
- `lastIds`（在 `flow` 上，可有可無）：刪了也不重用的 id 已經發到第幾號，例：`{ "p": 3, "t": 2, "r": 1, "g": 2 }` 是環節發到 `p3`、
  一次發到 `t2`、全上發到 `r1`、組發到 `g2`。新的 id 從這個號碼和流程裡現有的 id 裡最大的那個往下發。
- 檢查（不對就是「flow.json 壞掉了」）：
  - 有 `successRate` 就至少有一個環節（第 7 版起）。
  - `kind` 在上面五種裡；`color` 在上面那 10 色裡；同一個動作裡環節的 `id` 不重複。
  - `beats`：音樂段的環節一定有（第 7 版起），口號段的環節不能有；`at`、`len` 是整數，從音樂的整拍開始，
    `len` 是 2 的倍數、至少 2（整拍），`0 ≤ at`、`at + len ≤ length`；環節之間不能重疊；音樂段的環節照 `beats.at` 的先後排。
  - `squad` 是組 id：字串，`g` 加編號（第 8 版起；第 7 版是從 1 連續、不跳號的正整數）；大類是騰翻或跳躍的動作
    （每個人自己算，不分組）不能有 `squad`；第 8 版以前沒有 `successRate` 的動作也不能有。
  - 每一次照「記一次」的規則：同一個動作裡 `id` 不重複；`date` 是真的日期；`marks` 至少一個（有 `blanks` 時可以是空的），只指到這個動作的環節，
    值只能是 `✓` `△` `✗`；`who` 對得上（分組的動作是動作裡現在有人的組 id，騰翻、跳躍是動作裡的隊員）；
    `practice` 是 `runThrough` 才有 `runThroughId`；有 `blanks` 就是整個做、至少一個、不重複，只指到這個動作的環節，而且那些環節沒有記號。

## 位置座標

流程核心、流程檔、場地 SVG 都用同一套座標，畫面不用翻轉：

- 單位是公尺，存真正的值，不四捨五入。
- 原點是中心 X（墊子正中心）。
- x 往畫面右邊為正。直放時第 1 條在 x 最小的那邊。
- y 往正面（裁判、畫面下面）為正。橫放時第 1 條在 y 最大的那邊。
- 站位裡一個人的位置寫成 `[x, y]`，例如 `"pos": { "m1": [0.0, -1.83] }` 是中心 X 往後（離裁判遠）1.83 m。

## 隊員

`members` 照名單順序（= 泳道順序）排，每人只有三個欄位加 id：

```json
{ "id": "m1", "name": "小A", "gender": "F", "globalRole": "top" }
```

- `gender`：`F` 或 `M`。`globalRole`：`base`（底層）或 `top`（上層），教練自己選，不依性別帶入。
- 最多 40 人（`MAX_MEMBERS`）。改名字（候補上場）不換 id，所以站位和動作都跟著這個人。
- 字數：流程名字（`flow.name`）最多 40 個字、隊員名字 20、動作名稱 20、站位名稱 20、自訂任務角色名稱 8、動作備註 200（`MAX_CHARS`，照看得到的字算，一個家庭 emoji 算一個字），只在編輯器裡新增、改那一欄時擋；開檔不檢查，超過的照樣打得開。
- `markers`（在 `flow` 上，可有可無）：標記用什麼。`number`：名單第幾個；`initial`：名字開頭的字。
  沒有就是 `number`。開頭字撞在一起時顯示什麼不存，打開時照名字算（規則在 `memberMarkers`）。

## 站位

```json
{ "id": "f2", "segmentId": "s1", "at": 41, "pos": { "m1": [0.0, -1.83] } }
```

- 時間記「哪個段 ＋ 段內時間」：`at` 是整數，音樂段是第幾個半拍，口號段是第幾個 0.1 秒。
  不存秒數，所以改 BPM 時站位留在同一拍，秒數跟著變。
- `formations` 照時間排；同一拍最多一張。每張站位都包含全隊每一個人。
- `name`（可有可無）：站位名稱，例：`"開場"`。沒有就只叫「站位 3」。存去頭尾空白的字，清成空白就拿掉。
- **開頭那張**：`formations[0]`，一定在、不能刪，永遠在流程開頭（第一段的時間 0，`at` = 0）。
  - 還沒有段時（新流程）它是 `"segmentId": null`。加第一段時指到那一段。
  - 規則是「跟著第一段」：刪段或調段順序讓別的段變成第一段時，開頭那張改到新的第一段、`at` 0，站位不會變多：
    - 新的第一段開頭本來就有站位就用那張（拿掉它的 `walks`）。原本的開頭那張段還在，就變成那一段開頭的一般站位；段刪掉了就跟著刪。
    - 沒有的話開頭那張自己搬過去（`id` 不變）：調段順序時整張搬（位置不變）；刪段時位置換成新的第一段開始那一刻大家所在的地方。
  - 加段可以加在最後，或插在某一段後面；不會插到第一段前面，所以開頭那張不動。
  - 刪段時段裡的動作、站位一起刪；別張站位的 `walks` 指到刪掉的段，那個人的設定拿掉（回到預設）。刪掉唯一的段，開頭那張回到 `"segmentId": null`。
  - 其他站位只能在有段之後插，`segmentId` 一定不是 null。
- 走位：兩張相鄰的站位叫 A（前）和 B（後）。一個人在 A、B 的位置不一樣，就走位一次；一樣就整段站著。
  出發之前站在 A 的位置，出發到到達之間直線等速（用全域秒數算，所以可以跨段），到達之後站在 B 的位置等。
  最後一張之後站著不動。
  - **沒設的人（預設）**：到達 = B。出發 = B 往前一個八拍（8 拍，用 B 所在音樂段的 BPM 換成秒數），但不早於 A。
    出發落進前一段、不在那一段的格子上時，往前取到那一段的格子上（音樂段半拍、口號段 0.1 秒）。
    B 在口號段，或 A、B 之間不到一個八拍：出發 = A（整段走）。
  - **自己設的**：存在 B 的 `walks`。計算時夾在 A、B 之間；夾完出發不早於到達（例如後來改了段長），就當作沒設，用預設。
- `walks`（可有可無）：隊員 id → 他從前一張走到這張的出發和到達。只有自己設過的人才有；開頭那張沒有。
  時間跟站位一樣記「哪個段 ＋ 段內時間」，所以改 BPM 時還是同一拍：

  ```json
  "walks": { "m6": { "depart": { "segmentId": "s1", "at": 48 }, "arrive": { "segmentId": "s1", "at": 64 } } }
  ```

  - 檢查：隊員 id 和段 id 要存在、`at` 是 ≥ 0 的整數、開頭那張不能有 `walks`。不對就是「flow.json 壞掉了」。
  - 刪站位時它的 `walks` 一起刪（段縮短連帶刪站位也一樣），後面那張的設定留著。刪隊員時，每張站位裡他的設定都清掉。
- 插站位插在播放頭所在的那一拍 t（半拍／0.1 秒，往前取），位置帶入那一刻大家走到的地方。
  插之前和插之後，每個人每一刻的位置都一樣：對原本 A→B 有走位（出發 s、到達 e）的人，
  還沒出發（t ≤ s）的人 B 記 [s, e]；正在走（s < t < e）的人新站位記 [s, t]、B 記 [t, e]；
  已經到（t ≥ e）的人新站位記 [s, e]。只在預設會算出不一樣時才寫進 `walks`。
- 新隊員在每一張站位各自排進那一張最靠近場地中心的空格點：格點是墊子上每一格的正中間（不在格線、接縫或墊子邊上），一格一個；
  一樣近時先排靠正面的，再先排左邊的。格點半格以內那一張已經有人就跳過，所以每一張的位置可能不一樣。
  格點都有人了才排場外：在墊子外 3/8 格（0.69 m）排，每 1/2 格一個（都是放大後的吸附點），
  圓點（半徑 0.3 m）整個在墊子外、也整個在外圍 1 m 以內。先在正面外從左到右排成一列（左右各超出墊子 1/4 格），
  排滿了沿著墊子左邊往後、再沿著右邊往後，最後排後面；有人站著的位置跳過。
  最小的場地（1 條）有 7 個格點、場外 36 個位置，所以 40 人一定不會疊在一起。

## 吸附

拖人時吸到格子裡的格線、1/4、1/2、3/4；放大 ×2 以上再多 1/8、3/8、5/8、7/8。
左右、前後同一套，格子從墊子邊往外延伸，所以墊子外 1 m 也照同一套。
吸附只影響拖人；檔案裡存的就是吸附後的公尺值，不另外記第幾格。
