# 流程檔格式

分層照規格（#15）的「流程檔格式」。讀寫都在流程核心：`writeFlowFile(flow, 音樂位元組)`、`readFlowFile(zip 位元組)`
（`src/lib/core/flow-file.ts`）。範例：`docs/samples/sample-flow.zip`（只用假名）。

## zip 裡有什麼

存成 `流程名.zip`：

```
flow.json        { "formatVersion": 4, "flow": { … } }
audio/a1.mp3     flow.audio 列出的音樂檔，原封不動（zip 裡不再壓縮）
audio/a2.m4a
```

- `flow.json` 只有 `formatVersion` 和 `flow` 兩層。延遲校正之類的本機設定不進檔。
- `flow` 的欄位：`name`、`field`（`strips`、`layout`: `vertical`／`horizontal`）、`timeRules`、`members`、
  `audio`、`segments`、`formations`、`customRoles`、`actions`，下面各節逐一說明。

## 版本（formatVersion）

- 現在是第 4 版。改了 `flow.json` 的格式就把 `FORMAT_VERSION` 加 1，並在 `UPGRADES` 補一步「第 n 版 → 第 n + 1 版」。
- 開舊版檔：一步一步升到現在的版本再打開；存檔一律存現在的版本。
  - 第 1 版 → 第 2 版：站位多了可有可無的 `walks`（見「站位」）。資料不用動，沒有 `walks` 就是全部用預設，
    所以每張站位裡的位置不變；但什麼時候走會照新的預設（先站著，最後一個八拍才走）。
  - 第 2 版 → 第 3 版：動作多了可有可無的 `cues`（見「動作的拍點」）。資料不用動，沒有 `cues` 就是沒有拍點。
  - 第 3 版 → 第 4 版：動作多了可有可無的 `color`（辨識色），站位多了可有可無的 `name`（站位名稱）。
    資料不用動，沒有 `color` 就是用大類的顏色，沒有 `name` 就是只顯示號碼。
- 開比編輯器新的檔：不打開，提示「這個流程檔是新版編輯器存的，請重新整理，更新編輯器」。
- 不是 zip、沒有 `flow.json`、JSON 壞掉、沒有 `formatVersion` 或 `flow`、舊版號但沒有升級步驟：提示「這不是流程檔」。
- `flow` 裡任何一個欄位的型別不對（例如位置不是 `[x, y]`、分類不在清單裡），或指到不存在的段、音樂檔、隊員：
  也是「這不是流程檔」，不會開到一半壞掉。

## 音樂檔

```json
"audio": [{ "id": "a1", "file": "audio/a1.mp3", "name": "第一首.mp3" }]
```

- `file` 是 zip 裡的路徑，`name` 是教練載入時的原始檔名（只給畫面顯示）。
- 只列有段在用的音樂檔；兩個音樂段可以指同一個（變速切段）。
- **缺音樂檔**（`file` 不在 zip 裡）照樣打開：指到它的音樂段標紅「找不到音樂」，點開段設定重新選檔；
  動作和站位都不動。缺的檔下次存檔也不會出現在 zip 裡。

## 段

```json
{ "id": "s1", "kind": "music", "audioId": "a1", "bpm": 150, "firstBeatSec": 0.42, "halfBeats": 192 }
{ "id": "s2", "kind": "chant", "tenths": 300 }
```

- 音樂段：`audioId` 還沒載入音樂時是 `null`；`firstBeatSec` 是第一拍在音樂檔的第幾秒；長度存半拍數。
- 口號段：長度存 0.1 秒數。

## 時間規則、自訂任務角色、動作

```json
"timeRules": { "on": true, "minChantSec": 30, "maxMusicSec": 120, "maxTotalSec": 180 },
"customRoles": [{ "id": "r1", "name": "旗手", "meaning": "拿隊旗跑場的人" }],
"actions": [{ "id": "x1", "segmentId": "s1", "category": "stunt", "name": "Lib", "start": 16, "length": 16,
              "note": "", "members": [{ "memberId": "m1", "role": "上層" }] }]
```

- 固定的 11 個任務角色不存，只存這支流程自己加的。
- 動作的 `category`：`stunt` `pyramid` `toss` `tumbling` `jump` `dance` `other`。
- 動作的 `color`（可有可無）：辨識色，`#rrggbb`。沒有就是用大類的顏色。
- `start`、`length` 是段內整數時間（音樂段半拍、口號段 0.1 秒）；`role` 存角色名稱，沒掛角色是 `null`。

### 動作的拍點（cues）

`cues`（可有可無，沒有就是沒有拍點）：這個動作的拍點。存在動作裡、從動作開始算，所以拖動作、改 BPM 時跟著走，
刪動作時一起刪。

```json
"cues": [{ "kind": "count", "at": 0, "len": 4, "word": "down", "who": null },
         { "kind": "motion", "at": 4, "len": 2, "word": "high V", "who": { "role": "上層" } }]
```

- `kind`：`count`（拍子）、`step`（步驟）、`motion`（手位）。
- `at`：從動作開始算第幾個半拍（0 = 動作開始那一刻）。`len`：幾個半拍長，一拍 = 2。
- `word`：拍子只能是 `down`、`up`；步驟、手位是教練寫的字，去掉頭尾空白後不能是空的。
- `who`：`null` 是動作裡全部的人；`{ "role": "上層" }` 是動作裡這個任務角色的人；`{ "member": "m1" }` 是這個隊員。
- 檢查（不對就是「這不是流程檔」）：
  - `at`、`len` 是整數；`len` 是 2 的倍數、至少 2，手位一定是 2；`0 ≤ at`、`at + len ≤ length`。
  - 只有音樂段的動作可以有拍點。
  - `who` 指到的任務角色要有人在這個動作裡掛著，隊員要在這個動作裡。
  - 不要求在整拍上：放的時候對齊音樂的整拍，但動作之後被拖半拍時，拍點跟著落在 &。

## 位置座標

流程核心、流程檔、場地 SVG 都用同一套座標，畫面不用翻轉：

- 單位是公尺，存真正的值，不四捨五入。
- 原點是中心 X（墊子正中心）。
- x 往畫面右邊為正。直放時第 1 條在 x 最小的那邊。
- y 往正面（裁判、畫面下面）為正。橫放時第 1 條在 y 最大的那邊。
- 站位裡一個人的位置寫成 `[x, y]`，例如 `"pos": { "m1": [0.0, -1.83] }` 是中心 X 往後（離裁判遠）1.83 m。

## 隊員

`members` 照名單順序（= 泳道順序）排，每人只有三個欄位加 id：

```json
{ "id": "m1", "name": "小A", "gender": "F", "globalRole": "top" }
```

- `gender`：`F` 或 `M`。`globalRole`：`base`（底層）或 `top`（上層），教練自己選，不依性別帶入。
- 最多 40 人。改名字（候補上場）不換 id，所以站位和動作都跟著這個人。

## 站位

```json
{ "id": "f2", "segmentId": "s1", "at": 41, "pos": { "m1": [0.0, -1.83] } }
```

- 時間記「哪個段 ＋ 段內時間」：`at` 是整數，音樂段是第幾個半拍，口號段是第幾個 0.1 秒。
  不存秒數，所以改 BPM 時站位留在同一拍，秒數跟著變。
- `formations` 照時間排；同一拍最多一張。每張站位都包含全隊每一個人。
- `name`（可有可無）：站位名稱，例：`"開場"`。沒有就只叫「站位 3」。存去頭尾空白的字，清成空白就拿掉。
- **開頭那張**：`formations[0]`，一定在、不能刪，永遠在流程開頭（第一段的時間 0，`at` = 0）。
  - 還沒有段時（新流程）它是 `"segmentId": null`。加第一段時指到那一段。
  - 規則是「跟著第一段」：之後如果做了刪段或調段順序，讓別的段變成第一段，開頭那張要改指到新的第一段、`at` 0。
    現在只能在最後加段，所以第一段一旦有了就不會變。
  - 其他站位只能在有段之後插，`segmentId` 一定不是 null。
- 走位：兩張相鄰的站位叫 A（前）和 B（後）。一個人在 A、B 的位置不一樣，就走位一次；一樣就整段站著。
  出發之前站在 A 的位置，出發到到達之間直線等速（用全域秒數算，所以可以跨段），到達之後站在 B 的位置等。
  最後一張之後站著不動。
  - **沒設的人（預設）**：到達 = B。出發 = B 往前一個八拍（8 拍，用 B 所在音樂段的 BPM 換成秒數），但不早於 A。
    出發落進前一段、不在那一段的格子上時，往前取到那一段的格子上（音樂段半拍、口號段 0.1 秒）。
    B 在口號段，或 A、B 之間不到一個八拍：出發 = A（整段走）。
  - **自己設的**：存在 B 的 `walks`。計算時夾在 A、B 之間；夾完出發不早於到達（例如後來改了段長），就當作沒設，用預設。
- `walks`（可有可無）：隊員 id → 他從前一張走到這張的出發和到達。只有自己設過的人才有；開頭那張沒有。
  時間跟站位一樣記「哪個段 ＋ 段內時間」，所以改 BPM 時還是同一拍：

  ```json
  "walks": { "m6": { "depart": { "segmentId": "s1", "at": 48 }, "arrive": { "segmentId": "s1", "at": 64 } } }
  ```

  - 檢查：隊員 id 和段 id 要存在、`at` 是 ≥ 0 的整數、開頭那張不能有 `walks`。不對就是「這不是流程檔」。
  - 刪站位時它的 `walks` 一起刪（段縮短連帶刪站位也一樣），後面那張的設定留著。刪隊員時，每張站位裡他的設定都清掉。
- 插站位插在播放頭所在的那一拍 t（半拍／0.1 秒，往前取），位置帶入那一刻大家走到的地方。
  插之前和插之後，每個人每一刻的位置都一樣：對原本 A→B 有走位（出發 s、到達 e）的人，
  還沒出發（t ≤ s）的人 B 記 [s, e]；正在走（s < t < e）的人新站位記 [s, t]、B 記 [t, e]；
  已經到（t ≥ e）的人新站位記 [s, e]。只在預設會算出不一樣時才寫進 `walks`。
- 新隊員加進每一張站位，在墊子外半格（0.91 m，還在外圍 1 m 以內）排成一排，每 1/4 格一個（都是吸附點）：
  從正面左邊那個角開始往右，排到墊子右邊外半格；排滿了從那個角沿著墊子左邊往後排，排到墊子後面外半格。
  有人站著的位置跳過。最小的場地（1 條）也排得下 41 個位置，所以 40 人一定不會疊在一起。

## 吸附

拖人時吸到格子裡的格線、1/4、1/2、3/4；放大 ×2 以上再多 1/8、3/8、5/8、7/8。
左右、前後同一套，格子從墊子邊往外延伸，所以墊子外 1 m 也照同一套。
吸附只影響拖人；檔案裡存的就是吸附後的公尺值，不另外記第幾格。

## 場地尺寸

- 一格 = 一條的寬 = 6 呎 = 1.8288 m；一條長 42 呎 = 7 格 = 12.8016 m。
- 規格寫的 1.83、12.80、16.46、9.14 m 是這些值四捨五入的結果。
- 墊子外留 1 m，隊員也能站。
